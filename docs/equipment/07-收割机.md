# 收割机：设计、操作与实现

基线：0.5.1。采摘本格成熟农作物，并按原版HAMMER回调拆开巨大农产物，果实与种子进车辆货仓。

## 参数与操作

| 项目 | 实现 |
|---|---|
| prefab / 类型 | `aom_harvester` / `harvester` |
| 配方 | 木板8、绳子4、燧石16、齿轮2；园艺栏，炼金引擎 |
| 机械耐久 / 维修 | 40；地面燧石每份+10 |
| 物料 | 无；货仓存放果实、种子及其他产物 |
| 成本 / 速度 | 实际收割或拆分一格油、底盘、机械耐久各1；约4.2857世界单位/秒 |
| 挂载位置 | 独立实体位于车前，其余五种挂件在车后 |

挂载后按F经过成熟作物或已落地巨大产物。普通采摘和巨大物拆分在同格只结算一次，不按植株数扣机械成本。仓满先腾空间再F；仅拾取既有普通散落物不收费。

不会采浆果丛等非农作物，不收未成熟作物；不拆建筑、打蜡巨大装饰，不处理由其他库存持有的巨大物品。

## 普通采摘与产物归属

[aom_farm_work.Harvest](../../mod/Tractor/scripts/aom_farm_work.lua)先收本格散落物，再筛选同格真实农作物和Pickable.CanBePicked。以当前驾驶员作为Pick调用的采摘者，保留原版产量、种子、事件与角色回调。

同步采摘期间临时拦截驾驶员Inventory.GiveItem，只将本次新生成且无归属的产物留在原株位置，由车仓接收；不先合进玩家已有堆叠再搬走，也不扫描拿走玩家原有物品。回调结束无论成功或异常都会恢复原方法。

真实采摘状态变化才算成功。若已经生成产物但onpickedfn报错，将该株原版picked状态持久化，避免重试/读档复制同一产量；保留真实产物，WORK_ERROR停工并结算本格已发生改动。

## 巨大作物处理

巨大产物白名单从原版PLANT_DEFS的product_oversized及其_rotten变体构造，同时要求oversized_veggie标签。只对Workable动作HAMMER且CanBeWorked的对象调用WorkedBy，并以工作量减少或实体移除核验效果。

处理采摘新生成的巨大物时，若原版回调暂将它交给驾驶员，则只将这件本次新产物放回原株位置再拆，不转移无关持有物。之后再次扫描本格无主巨大产物，覆盖回调直接落地和此前已采下的巨大物。

拆分掉落仍由原版回调生成，不人工拼产物清单；本次散到格边的产物可捕获入仓，相邻格旧物不扫描。未拆完、异常或仍有成熟目标返回HARVEST_INCOMPLETE或WORK_ERROR，保留现场，已有改动按格收一次费用。

## 保存、动画与验证

货物跟随原版Container保存，机械耐久随配件保存。配比计划不会因收割自动重置；收获后如需下一轮，到播种面板显式重规划和确认。

机械显示保留原图单排收割齿，从左向右循环传动，结果碎叶无额外产物或农业效果。依据：[掉落与采摘适配](../../mod/Tractor/scripts/aom_farm_work.lua)、`test_harvester_flow.py`21项、`test_work_cargo.py`、`test_review_regressions.py`。已覆盖普通/巨大/腐烂巨大产物、打蜡保护、库存归属、仓满、回调异常与重试；真实多人画面和网络延迟仍待验收。
