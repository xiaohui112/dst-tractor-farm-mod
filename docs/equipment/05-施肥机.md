# 施肥机：设计、操作与实现

按农田的实际养分缺口逐份施肥。优先用车仓里合适的肥料，车仓补不了当前缺口时，从驾驶员的物品栏、已装备背包依次取用。

## 参数与操作

| 项目 | 实现 |
|---|---|
| prefab / 类型 | `aom_fertilizer` / `fertilizer` |
| 配方 | 木板2、绳子2、肥料桶2；园艺栏，炼金引擎 |
| 机械耐久 / 维修 | 独立200；地面燧石每份+50 |
| 养分目标 | 生长素、堆肥、粪肥三类各100 |
| 肥料来源 | 车仓 → 驾驶员物品栏 → 已装备背包，使用具有fertilizer组件的有效物品 |
| 结算 / 速度 | 实际施过一格，油/底盘/机械耐久各1；速度3世界单位/秒 |

1. 上车挂载。肥料可直接放在车仓、物品栏或已装备背包里。步行时也可手持肥料右键车身装进车仓。
2. 按F经过农田；挂件表盘显示机械耐久，货仓显示含堆叠的物品总数。
3. 当前格已满则跳过；缺某类养分且无对应肥料时，可保留缺口继续处理其他格。
4. 全部有效肥料耗尽、油尽或机械损坏时停工，补料/维修后按F继续。

肥料次数不是物品个数。桶装等有FiniteUses的物品按剩余次数计算，堆叠再乘数量；普通一次性肥料按每件一剂。空桶、零养分和异常数据不当作有效补给。

## 物料显示

货仓数字显示该仓内含堆叠的物品总数；一个剩3次的肥料桶仍计1件。机械耐久独立显示在挂件表盘。服务端在开工和作业时检查三个库存的实际肥料。

监听货仓肥料的stacksizechange和percentusedchange；事件闭包固定所属车辆，兼容原版首参为事件源的语义，取走物料或切换后解绑旧监听。

回收的腐烂物沿原版fertilizer组件使用；普通腐烂物的原版养分为0/8/0，一次消耗一份。可以先收割/清理入仓，再换施肥机施用，不增加转化配方或额外肥效，不会使腐烂作物复活。此循环由test_crop_remains.py贯通验证。

## 选肥与整格执行

[aom_fertilizer.Read](../../mod/Tractor/scripts/aom_fertilizer.lua)读取原版FarmingManager的三类养分；非农田跳过，接口或数值不可用则NUTRIENTS_UNAVAILABLE停工。

Select按车仓、驾驶员物品栏、已装备背包的顺序查找。每处库存按有效养分占比、有效增量、槽位顺序挑选肥料。每施用一剂都根据新的养分缺口与库存重新选择。

WorkTile在有缺口时检查油量，循环选择、施用、复读，最多300次防止异常不收敛。每剂调用原版AddTileNutrients，再确认变化且仅调用一次fertilizer.OnApplied；多次用量物品不预先拆走整件。原版用量、声音和部署附加回调保留，整格机械成本由驾驶层统一结算。

当本格没有可补缺口的肥料，但库存仍有可用于其他缺口的有效肥料时，返回可继续状态，不关闭整台设备。例如只有粪便、该格粪肥已满而另外两类不足，可以继续驶往其他地块。库存完全无有效肥料才报告缺料停工。

## 异常、保存与兼容

无变化不消耗机械资源。加养分后读取不可用、消耗或附加回调报错时，保留实际变化与已发生消耗，返回部分成功并停工，不重复补同一份养分。

机械耐久随挂件保存。肥料由各自的原版库存与物品组件保存，在原槽位消耗次数或堆叠。

支持范围由fertilizer组件决定，养分跟随游戏和其他Mod实际值，不在文档复制一份易过时的原版肥料数值表。目标100是当前模块常量，不是配置菜单选项。
