# 洒水机：设计、操作与实现

基线：0.5.1。按土壤实际缺口补水，以一次原版普通水壶用量为水箱单位；音乐和植物安抚由独立模块处理。

## 参数

| 项目 | 实现 |
|---|---|
| prefab / 类型 | `aom_irrigator` / `irrigator` |
| 配方 | 木板6、绳子4、水球6、冰块12；园艺栏，炼金引擎 |
| 水箱 | 出厂0剂；容量TUNING.WATERINGCAN_USES，默认40剂 |
| 水分剂量 / 上限 | 跟随TUNING，默认每剂25、土壤上限100 |
| 机械耐久 / 维修 | 独立60；燧石每份+10，修理不补水 |
| 结算 / 速度 | 实际浇过一格，油/底盘/机械耐久各1；约5.5714世界单位/秒 |

## 操作与补水

挂载后补水，按F经过农田，干地默认一趟用4剂补满；已满不重复浇，停车不重复处理。最后一剂尽量完成当前操作，然后缺水停工，不透支下一格。

优先驾驶到池塘边，右键池塘“补满水箱”，无需下车或水壶。服务端要求当前车真实挂有洒水机，水源带pond与watersource标签且组件available，距离不超过3加双方碰撞半径。调用水源Use后填满可用容量；结冰或不可用水源拒绝，满罐不再次使用水源。不扩展到海水或任意无pond标签的水源。

也可下车手持普通/高级水壶或冰块右键车辆补水。水壶需FiniteUses和fillable，按实际转入剂数扣壶内次数，空壶保留；高级壶不改变每剂效果。冰每份补1剂，仅消耗一份。池塘取水及装水交互不收农业燃料与耐久。

## 按需洒水实现

[aom_irrigator.WaterTile](../../mod/Tractor/scripts/aom_irrigator.lua)判断农田与实时水分，已满返回无变化；有缺口时检查燃料，然后在整格工序内部逐剂循环。每剂先从设备水箱扣1，再调用Soil.Apply并复读，达到上限立即结束。驾驶层对这一整格只结算一次，不应把外层limit从1改4。

[aom_soil_moisture](../../mod/Tractor/scripts/aom_soil_moisture.lua)读取原版IsSoilMoistAtPoint闭包中的实时_moisturegrid，无缓存自建水分表；格中没有独立值时使用世界wetness，并按原版上限钳制。通过AddSoilMoistureAtPoint应用一剂，再核对实际变化。

读取依赖debug.getupvalue及原版闭包结构，无法适配时安全返回MOISTURE_UNAVAILABLE。确认无效果会退回本剂水；已执行但事后无法确认时保守保留水消耗并停工，防止退水后重复得到水分。部分成功也保留真实进度并按格结算。

`aom_farm_work.Water`只转发一次Soil.Apply，供兼容入口使用；整格循环、水箱与补水均在Irrigator模块，不存在三处重复的补满算法。

## 音乐与安抚

世界IRRIGATOR_MUSIC默认开启，本车开关默认开启且随车保存。配件栏音乐按钮同时控制声音和服务端植物安抚；关闭不影响洒水或F开关。世界关闭或运行音频缺失时入口禁用。

激活要求挂洒水机、作业开启、有水、有油及音乐可用。服务端在作业状态变化和每秒调用附近可照料植物的TendTo，范围使用PHONOGRAPH_TEND_RANGE，默认8；同阶段已照料不重复计，停车可以安抚新阶段，不额外耗水、油或耐久。

客户端每个听者选择20单位内最近的激活车辆，最多播放一首《兰花草》，音量随距离衰减。听音范围20与安抚范围8是两套逻辑。播放失败清理本地句柄，不中断洒水；音频资源在`mod/Tractor/sound`，源WAV/MP3不是运行资源。

## 持久化与证据

水量由设备FiniteUses保存，机械耐久保存在独立_aom_machine_uses。新罐空/半/满都显式保存；旧版缺省满罐迁移到现容量，旧空罐不变满。卸载、维修、换驾驶员不重置水量。

回归：`test_irrigator_flow.py`、`test_pond_refill.py`、`test_irrigator_music.py`、`test_music_tending.py`。覆盖满水、零油、剂量、返回、雨水、补给、最后一剂、存档与开关；客户端听感、延迟、喷头对齐仍需实机验收。
