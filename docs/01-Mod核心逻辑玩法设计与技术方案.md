# Mod核心逻辑、玩法设计与技术方案

基线：0.5.8，2026-11-13；以代码及本版验证记录为准。依据为[modmain](../mod/Tractor/modmain.lua)、[驾驶模块](../mod/Tractor/scripts/aom_drive.lua)、[设备定义](../mod/Tractor/scripts/aom_equipment_defs.lua)及各设备实现。本文统一跨设备规则；设备专属设计见[文档导航](README.md)。

## 1. 玩法定位与边界

玩家驾驶拖拉机，在一个独立挂点上更换六种农场设备，完成开垦、播种、洒水、施肥、除草和收割。Mod自动执行原版组件提供的农业行为，保留原版作物生长、季节、压力、每份水肥效果和产物回调；增加机械资源成本、配比规划和原版植物安抚的自动调用。

配比只帮助满足位置、季节与养分互补条件，水分、照料、杂草、生长阶段等仍由原版判定，不保证任何环境下都巨大化。普通生物战斗、非农田灌溉与任意地形改造不属于这些工序的功能。

七种设备均在园艺栏首次通过炼金引擎解锁，制作后直接放置。六种挂件是不可手持的独立世界实体；货仓15格全部装货与物料。旧打包物品和旧仓库挂件只为存档恢复保留。

## 2. 完整玩家循环

1. 制作拖拉机及当前需要的挂件，右键有油的拖拉机上车。
2. 靠近地面挂件并右键挂载；每车同时只挂一件。
3. 将种子、肥料放入任意货仓格；洒水机从池塘、水壶或冰补水。
4. 按F开启作业，驾驶经过地块；再按F关闭。松键不关闭，停车不重复农业作业。
5. 普通流程为开垦→播种→水肥与养护→收割；缺料、损坏或仓满时处理原因并按F继续。
6. 开垦机统一准备九宫格；配比播种自动扫描周围九格、识别已有作物，优先补完本轮，新方案先筛应季，再按四格→两格→单格范围、最后按本次可补种数量降序选择整套余料足够的模板。无预览确认，完成后自动开始下一片，缺种则提示停工。
7. 右键挂件图标或已挂设备卸载到空地；驾驶时拿起燧石左键挂件图标修已挂件，或手持燧石右键地面配件；拿起齿轮点生命/底盘图标分别修理。

挂卸、下车、切换播种策略会停工；新驾驶员不会自动继承持续作业。仓库可在驾驶中查看，左键自己/车体或点击货仓表盘开关，右键自己/车体下车。

## 3. 地块采样与速度

[aom_work_profile](../mod/Tractor/scripts/aom_work_profile.lua)定义：地皮边长4世界单位，采样间隔0.1秒，空驶速度6世界单位/秒。开启作业后，速度为`6 × 设备参考mph / 7`；mph用于相对比例，不是物理单位换算，也不表示真实产能。

| 设备 | 参考mph | 游戏作业速度（世界单位/秒） |
|---|---:|---:|
| 开垦机 | 3.75 | 3.2143 |
| 播种机 | 5.5 | 4.7143 |
| 洒水机 | 6.5 | 5.5714 |
| 施肥机 | 7 | 6 |
| 除草机 | 5 | 4.2857 |
| 收割机 | 5 | 4.2857 |

TrackMovement按骑手位置遍历两次采样之间真正经过的网格，防止速度较快时漏格；对角穿过角点只计对角格。单次位移超过16世界单位视为传送，只处理终点，不沿途耕种。首次采样处理当前格；同格停车不重做，离开后再驶入按实时状态判断。

原版骑乘预测速度在切换作业时同步更新。设备数量、地块面积和机器数量的实际性能仍需实机测量。

## 4. 结算与失败恢复

WorkHere执行一个结算单位，WorkTile负责地块批次；播种一格最多尝试10颗，其他设备调用一次整格工序。

| 工序 | 结算单位 | 每单位燃料/底盘/配件机械耐久 |
|---|---|---|
| 播种 | 成功种下一颗 | 各1 |
| 开垦、洒水、施肥、除草、收割 | 本格出现农业改动 | 各1 |
| 只拾取、无目标、满水/满养分、无匹配配比 | 无农业改动 | 各0 |

水剂、肥料份数和种子另按实际使用扣除。洒水/施肥的循环在专属模块内部，一格用了多剂也只结算一次机械成本。两者先判断地块是否需要处理，再检查燃料；这不是免油。燃料不足拒绝消耗，不允许扣成负数。

工作区新增行驶成本，尚未打包安装：服务器在骑乘期间每0.1秒采样骑手位置，每4距离扣1燃料，与上述农业成本叠加；空驶、无挂件及关闭作业均生效，停车、原地转向、静止取水不扣行驶油量。超过16距离的单次跳变按传送重置起点；原版mounted事件重置落座后的起点，下车前结算最后一小段路程并取消任务，避免反复上下车免油。小数油量直接沿用net_float及原油量存档，无隐藏计费余量。油尽同时把服务端坐骑速度和客户端骑乘预测速度设零、停止移动及农业作业并头顶提示；允许原版下车及驾驶图标加油，加油恢复行驶，作业需按F重开。任务使用模拟时间，暂停期间不执行。

内部结果包含`changed / complete / reason / position / error`。是否产生真实农业变化与是否完成整格分开：部分完成后仓满、缺水或回调异常，保留现场并按实际改动结算一次；未改动则不收机械成本。

原版回调可能在变更实体后报错。aom_work_result观察真实副作用；底盘耐久、配件耐久及结果特效独立保护，一个回调失败不跳过其他结算。错误返回驾驶批次后扣应计燃料、停工并保留服务端日志。临时库存/掉落方法、NOBLOCK标签和配件结算归属会清理。采摘已产出但回调报错时，记录为已采摘，防止重试或读档复制产物。

`NEXT_TILE`对开垦机与播种机都是非停机提示；完成计划返回`COMPLETE`并保留索引，不自动重置。其余缺料、缺油、零耐久、仓满和不可继续的失败均通过状态码提示恢复方式。

腐烂植物职责：aom_crop_state集中识别作物、腐烂状态及可清理残株。收割机沿原版Pickable处理可采收腐烂株，货仓按spoiled_food预判叠堆；除草机仅对无法采收且明确腐烂/死亡的农作物执行原版DIG，保留原掉落和护田事件。残株也作为原始除草目标，先清其10距离内的刺针旋花；批内返生或重新可采收时重新判定并保留。开垦/播种不自动清植物，水肥不使腐烂作物复活。回收腐烂物可由施肥机按原版肥效使用；未开工时保留腐烂株返生，采收则移除原株。

## 5. 所有权与统一拾取

[aom_attachment_mount](../mod/Tractor/scripts/aom_attachment_mount.lua)保存车辆与挂件关联；装载时关闭挂件碰撞并由车辆记录保存；服务器将其父节点设为当前骑手（停放时为车辆），继承连续移动与转向，客户端不周期写世界坐标。工作区快速修复将挂件切到aom_attachment_mounted动画bank：按mount-layout.json逐设备、逐视图对齐连接点，正前后、侧向及镜像斜向共享同一套父变换；微小的正负局部位移只保留前后深度排序，卸载恢复独立摆放bank。水肥流使用相同挂载偏移。全部六种配件在移动作业时每0.3秒从驾驶动画的烟筒定位符号排烟；停车/停工停止新增烟雾，符号不可用时不回退到车身原点。上下车立即重绑，卸载先解除父关系，再恢复独立世界持久化。服务端核验骑手、归属、距离、实际设备和机械耐久。挂载期间监听设备onremove，直接删除时先清空关联、解除删除/父节点监听，再停工并广播变化；同步挂件类型、耐久与水量，移除旧耐久监听。正常卸载取消删除监听，旧设备删除不会影响新设备。读取、挂卸与保存会检查旧失效引用并恢复空挂点；已删除设备不重新生成，也不走卸载落地流程。

开垦、除草、收割在地块内收纳可拾取散落物，并捕获本次回调的新掉落。因此本次散到格外的产物可以入仓，相邻格原有物品不会被额外扫描拾取。燃烧物、投射中的物品、打开的容器、已归他人的物品和巨大产物不按普通散落物直接收纳。

库存使用原版Container叠堆及归属机制。开垦和除草容量不足时保留地面余量并暂停。收割机采用选择性收纳：15格都占用时，只采主产物已有兼容未满堆叠的作物，其他作物留在原地；装不下的真实种子/副产物和旧地面物保留地面，不阻断其他可叠堆作物。存在空格时允许收新品种；所有槽位及堆叠均无空间时CARGO_FULL停工并提示，跳过不可收品种不收费也不停驶。实际收纳仍用原版CanAcceptCount/GiveItem，保留皮肤及自定义叠堆约束，不预生成产物、不提前掷随机掉落。

## 6. 客户端、服务端与界面

服务端负责农业、物料、耐久、挂卸、自动配比选择与存档。客户端负责输入请求、仪表和声音，不执行第二份农业结算。面板RPC通过GetDrivenTractor核验当前骑手、死亡/幽灵和busy状态；F按键避开聊天、暂停与禁用控制器，并拦截同一次原版攻击输入。

五个表盘依次展示生命、底盘耐久、油量、货仓物品总数、挂件机械耐久；洒水追加水滴表盘。生命/底盘/燃料悬停仅一行名称与数值，其他挂件仅名称和耐久两行，播种机为名称、耐久、当前策略三行，货仓仅格数及含堆叠物品总数两行，去掉作业原因、操作长说明与车速；异常及操作结果在人物头顶显示。播种机空手左键配件表盘直接循环顺序/随机/配比策略，移除原下方切换箭头与方块；配比模式自动匹配周围九格的九宫格模板，不再显示规划控件，拿起物品点击优先走维修；右键配件表盘卸载。驾驶时拿起齿轮左键生命或底盘图标，每份只修对应数值100；拿起燧石左键挂件图标，每份修10机械耐久；拿起燃料左键燃料图标按原版值加油。服务端从当前活动物品读取材料，重新核验请求车体、真实骑手和上限，满值或失败不消耗；六种地面配件也允许驾驶拖拉机时手持燧石右键修理，保持距离及归属校验。步行齿轮右键车体/残骸仍沿用同时修复两项。播种机满耐久400，水箱400，维修不补水或物料。音乐由Mod设置开启/关闭/静音控制，静音保留安抚；池塘补水5秒，车尾朝水并显示软管。配置项仍为语言、模型倍率和洒水音乐。

货仓为原版15格Container，客户端单排15格左对齐融合在原版物品栏上方、状态图标下方，使用原版槽位及物品栏木质底图，取消标题/说明文字。通过原版type=inv挂入inventorybar.toprow_inv，随物品栏及背包布局重建保留；继承一次物品栏缩放，容器自身倍率固定1避免重复缩放。表盘及播种设置位置不随货仓开关变化。货仓逐格读取人物前15格的真实横坐标，包括5/6及10/11的分组间距；slotposfn用于打开时布局，原版Rebuild触发RefreshPosition时重排全部货仓槽位并调整背景宽度。无HUD时按原版68格宽、12普通间隔及28分组间隔回退。支持原版拖放、堆叠、快捷转移与开关仓库；货物仍归车体，未将拖拉机改成角色装备的背包。旧档1～15格先按索引恢复，第16格再合并堆叠或放空格，余量通过原版GiveItem完整落在车旁。

原因码与参数以一个`_workstate_net`字符串发布，通过aom_work_status.Read解析，各客户端独立翻译；不能直接用中文提示判断业务。同组其他netvar可共用dirty事件，事件表示重读整组，不提供跨netvar原子快照。旧规划网络字段保留兼容；客户端不再创建绿色预览或确认按钮，只清理可能残留的旧预览标记。自动选择与实际坑位进度由服务器维护。

异常反馈统一显示在操作人物头顶，使用原版talker与默认文字样式。加油、维修、装料、挂卸、池塘补水及鼠标开仓失败返回明确原因码，由原版actionfailed→GetActionFailString→talker.Say处理；只注册本Mod动作的失败文案，保留原版哑剧角色行为。作业停工、自动配比缺种、按键与面板RPC失败由服务端直接喊话。相同作业原因和参数只在变化时提示，主动重试可再次提示；正常空地经过不刷屏。原因码仍同步供内部判断，表盘只保留简短关键数据。补水中断时提示已保留补入水量，正常完成及保存取消不额外提示。

工作区继续修复0.5.7实机喊话过高：驾驶bank有效时跟随headbase，GetSymbolPosition局部偏移改为零，通过FollowText.SetScreenOffset额外上移56屏幕单位，避免再次受模型或头部矩阵倍率影响。保留原版台词、字体和广播；已有、延迟创建、替换的控件保持间距且不累加。下车、删车、换车恢复原offset_fn、symbol及屏幕偏移，保留其他Mod随后写入的偏移。

0.5.8后工作区补正（未发布）：原版ApplyBuildOverrides只在服务器执行，客户端没有_aom_driver_animstate标记；客户端改用同步_rider_net及驾驶资源可用性识别驾驶状态。服务端上车立即设置锚点，客户端aomriderdirty立即更新；ontalk在原版创建FollowText之后同步修正首句/新控件，退出时移除监听。原版骑牛idle宽方向掩码及侧向run均可能仍用正脸，侧向驾驶改用player_idles.zip的真正侧脸姿势；正后方复用背向骑乘姿势，行驶、待机和对话都保持固定坐姿并随车身悬挂移动。五种后挂件（含播种机）在挂载bank的正面视角全部遮挡，包括水肥工作层；地面设备仍完整显示，收割机各方向保持可见。无挂件表盘隐藏中央图标，保留空表盘和“—”数值。

工作区补充：水滴悬停仅水量/容量一行；音乐使用客户端静态任务检测暂停，暂停停音，恢复后重新核验作业条件再播放。安抚由服务端模拟时钟控制，静音仍有效。死亡使用交付death.png编译的wreck符号（矩阵倍率1），半尺寸仅用于收纳态；保留车体配置倍率，五方向暂共用单张残骸图。

开垦补充：新地遇植物或固定障碍整格跳过；已有农田避开植物周围原版间距范围内的坑位，包括邻格植物。占用、不可DIG障碍及不可铺地不终止连续驾驶；仓满、清理回调未完成、资源耗尽及异常仍停工。IsFieldReady仍严格判定完成；开垦与播种策略解耦，始终准备普通九宫格；自动播种核验实际坑位与已有作物，不虚增已种数量。

## 7. 存档与生命周期

| 对象 | 持久内容 | 恢复规则 |
|---|---|---|
| 拖拉机 | 油量、原版健康/底盘/货仓、独立挂件记录、策略、配比计划 | 恢复数据与挂件，作业保持关闭 |
| 地面挂件 | 机械耐久；洒水机另有水量 | 世界单独保存，不与车上记录重复 |
| 配比 | v3布局ID、季节、起点、旋转、成功索引，新增automatic与实际positions | 不需要玩家确认；旧规划按现场识别，自动方案继续核验余料和作物 |
| 旧打包车 | 油量/耐久/生命/货物/策略/计划等旧记录 | 找到合法落点后才离开原库存，受阻保留归属并每5秒重试 |
| 损毁车 | 残骸及车体状态 | 死亡强制下车，落货与配件，残骸保留，可齿轮维修或锤拆 |

活动定时器、工作循环和结果FX不作为作业状态保存。一轮完成后可自动选择下一片或收获后重整的区域；新方案重新识别现场，不套用旧成功索引。

成熟刺针旋花：除草机以本格原始作业目标为中心，优先按原版DIG清理其10距离内的刺花（去重且只扩展一层，普通杂草仍限本格）；收割前按各植株的原版护田范围预检，发现成熟未燃烧刺花以IVY_THREAT停工且未发生采摘不收费。挂载收割机时不再自动破根须，开工/停工均适用；除草机保留破圈兜底，其他挂件原有兜底不变。破圈只针对本车/当前骑手，保留原版反击伤害，不影响其他玩家或步行状态。

0.5.8音频规则：工作声采用试听C（SFXMint Cab Tractor 02，CC0），单声道循环6.88秒，处理接缝并匹配本机原版园艺耕地机循环样本约-15.5 LUFS，峰值上限-3 dBTP。工作声调用音量1、使用set_sfx；idle/drive保留原有源音与音量0.45。洒水音乐匹配同一采样响度，调用音量1并继续使用set_music及20距离衰减；实际混音受游戏音量和距离影响。洒水机作业且音乐on时不播放拖拉机idle/drive/work，只播音乐；off/mute时播放拖拉机音效，mute仍安抚植物。缺音乐资源时回退机械声；停工、缺水、换挂与上下车按实时状态重选，暂停停音乐。
