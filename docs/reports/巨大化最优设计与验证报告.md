# 巨大化·最优：设计与验证报告

核对基线：0.5.24源码，2026-11-17。算法实现位于 `mod/Tractor/scripts`，以下链接直接指向拥有该行为的模块。性能数据采用明确标注的冻结版本；本文不是一次新测速报告。历史演进见[开发日志](../02-开发进度.md)。

## 1. 背景与问题定义

农田包含真实坐标的土坑，种子数量有限，作物的应季、同族与养分规则互相制约。仅按单格固定配方填田会浪费跨地皮同族关系和库存尾数；仅追求坑位全满又会破坏养分互补或同族条件。因此这里解决的是带空间约束、库存约束和逐格平衡约束的离散优化问题。

游戏运行环境是服务端Lua 5.1。求解必须能暂停、跨帧推进、响应输入变化，并输出可以按实际土坑执行的计划。当前采用Lua中的组合枚举、动态规划上界、构造与完整约束搜索，不在游戏内调用Python、OR-Tools或CP-SAT。

“最优”指在本次扫描到的合法坑位、当前库存、季节和规则下，最大播种数量已被证明。它不表示所有农田都能种满，也不表示同族排列、计算用时或最终巨大化率全局最优。

## 2. 输入、扫描与约束

[动态入口](../../mod/Tractor/scripts/aom_dynamic_farm.lua)从起点做四边连通扫描，识别完整空九宫格；索引只加速发现，不能替代现场。缺坑、障碍、已有不匹配作物的地皮不作为连接桥梁。最优上限64块，即标准新田最多576坑；超限返回错误，不暗中截取前64块。模版策略使用独立整块选配入口，无该固定上限。

| 输入/约束 | 当前语义 | 所属实现 |
|---|---|---|
| 应季 | 只用原版good_seasons允许的作物 | aom_seed_layout.Crops |
| 库存 | 每种用量不超过可识别种子库存；随机种子不参与巨大化配比 | aom_seed_strategy、AttachmentStore |
| 坑位 | 每坑至多一株，可留空；按实际世界坐标 | aom_dynamic_farm、aom_seed_layout |
| 同族 | 原版半径内同种数量达到family_min_count，含自身；默认半径4、最低4株 | aom_farm_neighbors、Layout.Valid |
| 坑距 | 按原版GetFarmTillSpacing范围建立冲突，默认1.25；范围内不同坑不能同时占用 | aom_farm_neighbors |
| 密度 | 每地皮不超过原版拥挤阈值；九坑容量通常更紧 | aom_seed_layout、动态校验 |
| 养分 | 每地皮三种养分净变化分别为零，不能跨地皮抵消 | aom_seed_balance、Layout.Valid |
| 特定通用结构 | 双种单格4＋4保留中心空坑，库存多不补成5＋4 | 候选构造、校验 |

不读取当前土壤肥力，不以贫瘠为由拒播或提示缺肥。逐格养分净零只说明配比消耗与回补相抵，不保证每个时刻都有足够养分；水分、照料、杂草和后续压力仍需游戏中养护。

设坑位集合P、作物集合C，变量x[p,c]取0或1，表示该坑种该作物。约束包括每坑Σc x≤1、每种Σp x≤库存；对每个地皮t和养分维度k，Σp∈t,c v[c,k]x[p,c]=0。若x[p,c]=1，则其原版邻域内Σq x[q,c]≥该作物同族下限。冲突坑对不能同时占用。这是理解实现的数学描述，游戏代码并不构建通用整数规划求解器。

净变化向量v来自原版PLANT_DEFS的消耗及回补定义，经[aom_seed_balance](../../mod/Tractor/scripts/aom_seed_balance.lua)推导，不硬编码秋季、指定作物或指定库存的答案。三维平衡中可以利用线性关系缩减固定目标配额求解的自由度，但最终仍检查三维净变化。

## 3. 原版浮点与九宫格设计

此前理想4/3偏移在Lua double中会产生16.000000000000007等边界值；坐标存入原版float32后又会得到另一组误差。把坐标转为float32或加固定epsilon，都不能让后续Lua double距离运算等价于原版查询。几何图少边会同时导致同族误判、可行域缩小、数量偏低及证明搜索膨胀。

当前[aom_farm_neighbors](../../mod/Tractor/scripts/aom_farm_neighbors.lua)对实际坑位调用原版FindEntities，并把查询结果映射为邻接矩阵；包含实际坑位过滤、原版同族排除标签和不同作物半径，不用Lua距离平方再过滤一次。缓存按实际位置/半径保存，现场变化及续播由相应复验路径处理。[边界核对](../evidence/family-distance-2026-11-16/原版FindEntities边界核对.md)基于当时本机游戏二进制，不代表未来所有平台永不变化。

新空田由[aom_farm_grid](../../mod/Tractor/scripts/aom_farm_grid.lua)统一提供−1.3125、0、+1.3125偏移。21/16可被二进制精确表示；同格最短1.3125、跨格最近1.375，均严格大于原版1.25邻坑破坏半径。不能改成恰好1.25：原版清坑范围包含等号，新坑可能破坏邻坑。

旧存档/旧田仍按真实坐标识别，已有植物不移动；收获后重新开垦空田才能更新坑位。新坑距减少标准网格的数值边界问题，原版查询仍是合法性依据，不能因此假设任意偏移或任意大坐标都安全。

## 4. 目标顺序与证明范围

实现严格按以下顺序处理：

1. 满足所有硬约束。
2. 证明最大合法播种数量。
3. 固定数量后减少同族分散程度。
4. 继续比较最近同族距离，再比较排列整齐。

[aom_seed_layout](../../mod/Tractor/scripts/aom_seed_layout.lua)按 `fragmentation → family → tidy` 比较；旧加权score只作诊断。更多种类、占地更少不作为压过这些目标的独立优先级。必要空坑不随意填补。

数量证明与排列证明是两回事。数量可以通过“合法见证达到安全上界”立即证明，也可以通过完整搜索排除所有更大目标后证明。排列在有限候选和工作量预算内优化，不宣称全局最优。不能因为一个启发式分支到预算、没有找到方案，就判该目标无解。

## 5. 求解流水线与设计理由

[aom_seed_packing](../../mod/Tractor/scripts/aom_seed_packing.lua)把求解分为数量和排列两个阶段，避免每个中间候选都重复花预算整理。

| 阶段 | 主要工作 | 结果如何使用 |
|---|---|---|
| 规则归一 | 应季作物筛选、原版净变化向量、真实空间邻接 | 建立同一个可行域 |
| 单格枚举与数量上界 | 枚举至多九株的平衡组合，计算库存/容量连续放宽及整数配额上界 | 上界必须覆盖所有合法解 |
| 初始见证 | 通用几何、同族构造、静态目录提供的完整候选 | 只提高合法下界；构造失败不排除原问题 |
| 区域/配额见证 | 目标库存联立求解、互补子组、紧凑地皮子集、局部真实空间构造 | 达到上界且全田校验后可结束证明 |
| 完整后备搜索 | 原始坑位域、库存、逐格平衡、同族传播与冲突约束 | 达到上界，或排除更大目标后证明数量 |
| 固定数量整理 | 分散分量、同族距离、行列/跨格重复等候选调整 | 不改变已证明数量及硬约束 |
| 提交前校验 | 重新核对季节、库存、坑位及布局 | 输入变化重新计算，失败不交付假最优 |

[aom_seed_exact](../../mod/Tractor/scripts/aom_seed_exact.lua)包含坑位域传播、容量匹配、同族组覆盖、空闲区域连通约束、逐格组合与数量传播。固定目标配额可直接解出少数作物数量；同向量/同族条件的库存用规范代表减少对称枚举。复用不变候选上下界、同族域统计及完整排除的失败状态，减少重复工作。

完整证明与辅助构造交替推进，保留搜索栈。某条完整搜索已证明配额无解，可停止同配额的其它顺序；截断分支不能写入不可行缓存。区域构造失败或地皮子集失败，也不意味着全田无解。静态模版仅给最优提供额外见证，最优不调用模版策略选配入口；目录变化仍可能影响下界与耗时，需回归。

如果最大数量未证明，继续运行或由用户取消，不在某个时间上限后静默返回较小数量。64块是输入规模边界，不是最坏时间上界；一般完整组合搜索仍可能指数增长。

## 6. 游戏调度、缓存与失效

动态入口用Lua协程：前台每帧CPU软额度可在Mod设置选择2/4/8/12/16/24/32ms（默认4ms），后台固定1ms，世界共享以避免多车叠加预算；每次至多恢复1024次。预算在协程恢复后检查，单次恢复可能超额，因此不能承诺每帧严格不超过所选额度或固定FPS。保存设置并重新载入世界后生效；调大额度通常缩短等待，也会增加卡顿风险。

最优在骑乘空闲、挂播种机、无既有计划时每2秒核对输入；连续两次稳定才启动低额度预计算。预计算不消费物料，不自动开工；按F可接管有效任务。模版跳过这个后台入口，避免重复大田扫描。

完整方案最多缓存8项，最多保留4项暂停任务；签名包括实际坐标、应季库存、季节、规则、策略、网格/目录版本和锁定编号。库存排序换槽不应无意义失效；实际输入变化则重新扫描求解。缓存和协程不跨存档持久化。

完成后提交服务端计划并显示预览，2秒后开始播种；库存、季节、坑位和冲突在执行中复核。已播计划不能被新库存任意改种。原版回调异常按现场实际变化结算，记录完成进度避免重复种植；0.5.23挂件耐久在每格最后一坑实际成功时扣1。

头顶显示经过时间，保留内存quantity_seconds/arrangement_seconds等统计。前台结束时打印一次结果到服务端标准输出，并通过定向RPC送到驾驶者的本地控制台，包含实际经过时间、计算时间和所选额度，完成时附数量与排列分项；后台保持安静，不创建独立规划日志文件。CPU执行片段、端到端墙钟、游戏跨帧等待及预览2秒是不同口径。

## 7. CP-SAT离线研究结论

[首次冻结对照](../evidence/cpsat-offline-2026-11-16/结论.md)用相同48场景比较Lua、CP-SAT单线程和8线程，并选8场景各追加3轮。随后[float32复测](../evidence/cpsat-native-float32-2026-11-16/结论.md)发现Lua几何与原版模型不同，不能把两个可行域的速度直接当作求解器优劣。

当时float32输入、10秒数量预算下，Lua完成41/48、CP单线程36/48、8线程40/48；秋季3×3各40 Lua未完成，CP完成81株。但CP部分输出被当时Mod几何拒绝，这些是诊断证据，不是换求解器的验收数据。

最终采取原版范围查询统一和新坑距，保留Lua求解器。CP-SAT原型适合作离线数量/布局对照；不据旧快照结论宣称当前CP-SAT更快，也没有完成0.5.24的全量CP-SAT重测。可以借鉴域传播、安全上界、对称消除和失败状态复用，但具体收益必须在相同可行域、输入与预算下验证。

### 当前发布：0.5.24

[安装记录](../evidence/0.5.24-game-install-validation.json)：708项Lua 5.1行为回归、18项发布检查全部通过，0失败/错误/警告/跳过；99个运行文件在源码、ZIP和本机安装逐字节一致。新增可调前台预算及单次控制台结果，后台1ms不变。各档位调度、最终布局、后台接管、世界共享、配置入口与定向回传经过专项回归；真实客户端显示和新档位等待时间尚未实测。

### 执行成本基线：0.5.23

[安装记录](../evidence/0.5.23-game-install-validation.json)：698项Lua 5.1行为回归、18项发布检查全部通过，0失败/警告/跳过；98文件源码、ZIP和本机安装逐字节一致。这包含执行成本改变和原有规划/存档回归，不等于重新跑完所有历史性能矩阵。专项证据见[验证说明](../03-版本测试报告与Bug修复.md)。

### 新几何冻结复测：0.5.22

[完整报告](../evidence/grid-spacing-0.5.22/结果.md)及[48场景逐例对照](../evidence/grid-spacing-0.5.22/comparison.csv)记录两轮48场景全部完成最大数量证明、校验通过、数量与0.5.21一致。网页22项和CP/浮点14项通过，新坑位测试覆盖25格真实开垦后225个有效坑、旧田重整/邻格保护、已有作物及多个坐标原点。

| 秋季场景 | 策略 | 株数 | 总墙钟 | 数量阶段CPU |
|---|---|---:|---:|---:|
| 5×5，大蒜/洋葱/辣椒各100 | 最优，3轮中位数 | 225 | 2.930秒 | 1.411秒 |
| 5×5，九种应季各40 | 最优，3轮中位数 | 225 | 6.242秒 | 4.881秒 |
| 7×7，九种应季各40 | 最优，3轮中位数 | 340 | 5.078秒 | 2.336秒 |

## 9. 复现与限制

冻结Mod与输入，保存源码/原版定义哈希、完整布局、数量证明标志、数量/排列分项和墙钟；重复比较应交替方法、记录负载，排除时钟跳变或输入期间变更。网页直接调用Mod原始Lua，Python独立检查只验输出，不修正或替换布局。

```sh
python3 tools/seed_strategy_audit.py --suite all --jobs 4 --case-seconds 30 --output outputs/seed-regression.json
python3 tools/selfcheck.py --release
```

30秒是离线工具中断上限，不是游戏降级条件。超时不记为完成；未证明不填“最大数量”，仅排列未完成时应分别保留数量已证明状态。CP-SAT使用额外独立环境，见[原型说明](../../tools/cpsat_benchmark/README.md)。

真实客户端、原版引擎现场查询、多人/专服、巨大化完整生长和其它Mod组合仍需实测。开垦1.3125解决标准网格的已知边界，但不保证任意畸形坑位均可行；规则改变或其它Mod改变原版定义后必须重新验证。若继续优化，应优先定位数量证明与扫描/校验的实际占比，并使用同源同规则对照，避免作物或截图专用答案。
