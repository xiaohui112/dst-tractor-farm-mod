## Git只读诊断

`git count-objects -vH`显示4652个松散对象约3.84GiB，10个pack约27.51MiB，16个prune-packable，garbage为0。松散对象不等于垃圾，其中可能仍被提交/引用使用。应优先评估普通对象打包维护（另行执行），有机会利用压缩和差量降低占用；无法据此承诺释放多少空间。只有普通维护不足、又确需清除仍被历史引用的大资源时，才另行考虑历史重写与远端协调。本轮未运行gc/repack/prune或改写历史。

## 可操作的保留与删除边界

| 对象 | 建议 | 原因/验收 |
|---|---|---|
| 各处 `__pycache__`、旧 `.pyc` | 可删除，运行后再生 | 先停止正在执行的测试；不会缩小Git历史 |
| `.venv` 与 `outputs/*venv*` | 核对解释器后保留一套常用环境，其余可重建 | 环境不提交，CP-SAT与Python3.9/Lupa可能需要不同解释器，不能盲合并 |
| `.runtime` | 只清已结束job和旧服务记录，保留当前依赖 | service.json、jobs和Lupa在同一树；网页正在使用时不整体删 |
| 旧安装备份/重复冻结Mod | 核对后归档较早版本，保留最近回滚和关键冻结证据 | 备份单项可能含旧ZIP和多个目录，勿只按顶层名字判断 |
| outputs中的预览、重复解包和构建临时文件 | 确认可从现有源重建后可删 | 唯一见证、调试数据、尚未归档报告先转存 |
| `assets/driver/build` | 按读取引用逐文件确认 | 当前时间线来源gz并非可随便重建的临时文件 |
| `assets`原稿、FMOD工程、source-art、mount-layout | 保留 | 美术/音频构建与来源授权依赖，玩家不需要但开发需要 |
| `mod/Tractor/anim` | 保留 | 约89MiB是当前动画运行资源；需另做资源去重评估，不能直接删 |
| `docs/template-catalog`原图/catalog/fixtures | 保留 | 同时是构建/审核/测试输入，不是冗余文档 |
| 历史docs及旧证据 | 可外部归档；优先级低 | 总量很小，先保留追溯入口，不通过改写旧证据节省空间 |
| `.git` | 不手动删除内部目录 | 先读Git对象统计；日常维护未必能去掉仍被历史引用的大资源。彻底清理历史需另行方案并考虑远端协作 |
| 根目录 `Tractor.zip` | 保留当前交付一份 | 不在目录统计中；安装/分发使用，可由package_mod重建 |
| 旧Windows交付工具 | 不常用时可归档，收益很小 | 先核对用户是否仍需平台构建，保留必要历史说明 |

## 执行前后的验证

本报告不执行删除，也不提供自动批量删除命令。获准清理时应明确选中的路径，停止相关服务/任务，先留恢复清单；清理后检查当前安装包、构建输入、发布测试和网页启动。若未来只交付玩家包，用当前Tractor.zip即可，无需把整个开发仓库随包分发。
