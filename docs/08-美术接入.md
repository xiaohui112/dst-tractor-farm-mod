## 三、工具链安装（已在本机完成）

`ktech` / `krane` 没有官方 macOS 预编译包，需从源码构建：

```bash
brew install cmake pkg-config imagemagick

curl -sL https://codeload.github.com/dstmodders/ktools/tar.gz/refs/tags/v4.5.1 -o k.tgz
tar xzf k.tgz && cd ktools-4.5.1

# 新版 CMake 对老 CMakeLists 有策略限制，必须加这个参数
cmake -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DCMAKE_BUILD_TYPE=Release .

make -j8
cp ktech krane ~/.local/bin/     # 注意产物在源码根目录，不在 build/
```

验证：`ktech --version` 与 `krane --version` 均应输出 `4.5.1`。

## 四、为什么动画还是占位

| 事实 | 影响 |
|---|---|
| `krane` 只支持 `anim.zip → SCML` | 无法反向把 SCML 编回 `anim.zip` |
| SCML → anim.zip 只有 Klei 官方 **Mod Tools** 能做 | 官方工具仅 Windows，本机无 DST 环境 |
| 美术包提供的是 SCML + 分帧 PNG | 需要过一道官方编译器才能变成 build.bin / anim.bin |

所以 `anim/*.zip` 目前仍是脚本生成的**占位结构**：Mod 能正常加载不报错，但世界里的拖拉机会是空白。

## 五、拿到动画的两种补法

**补法 1（推荐）：在 Windows 上用 Mod Tools 编译**

1. 安装 DST 后，Steam 里找到 `Don't Starve Mod Tools`
2. 把 `anim/aom_tractor_chassis/`、`anim/aom_attachment_shared/`、`anim/aom_attachment_symbols/` 三个 SCML 工程分别编译
3. 把产出的 `build.bin` + `anim.bin` + 各 build 的贴图图集，打包成 `aom_tractor_chassis.zip` 等，覆盖 `mod/AgeOfMachines/anim/` 下同名文件
4. 注意：`aom_attachment_symbols` 需要的是**符号集**（7 个符号），不是 7 个动画，编译时留意这个区别

**补法 2：找有 Mod Tools 的朋友帮编译**，把产出的 zip 直接给我，我负责接入与验证。

## 六、美术包里的已知注意事项

- 美术包自述：车体在 256×256 画布中只占右下角，底部距画布边缘 16px。编译后若发现"浮空"，需要在 SCML 里调 pivot 或在游戏里调 `SetScale`
- `attachment` 车尾层 `z_index=0`，`body` 为1；收割台独立使用 `attachment_front` 车头层 `z_index=2`。收割台通过 SCML `(80,-9)` 偏移及水平镜像连接车头，其他配件保留车尾挂点
- 美术包的 `validation.json` 明确写了 `engine_compilation: not performed`、`game_validation: not performed`，即**从未经过游戏验证**
