# 驾驶室坐姿接入

已实现复用原版骑牛坐姿的驾驶显示代码，并准备好 Windows 编译源工程。最终驾驶动画需要在 Windows 上读取已安装的 DST 原版动画后生成；本机尚无最终游戏内画面的实机验证。

## Windows 操作

下载 `AgeOfMachines-Windows-Driver-Kit.zip`，完整解压到英文短路径，例如 `C:\AOM-Driver\`。

1. 双击 `Build-Driver.cmd`。
2. 如提示，选择完整 Mod Tools 目录中的 `scml.exe`。
3. 如提示，选择饥荒联机版安装根目录（包含 `data` 的目录）。
4. 成功后发回 `Driver-Results.zip`，不要只发一个动画 ZIP。

脚本使用 Mod Tools 自带 Python 2.7，也兼容 Python 3 标准库；不需要图像生成工具或额外 Python 包。包内中文说明包含故障处理。

## 动作与角色外观

上车仍由原版 `ACTIONS.MOUNT` / `Rider:Mount` 执行，下车由原版 `ACTIONS.DISMOUNT` / `ActualDismount` 执行。没有替换原版 rider 组件或角色状态机。

拖拉机通过原版 `ApplyBuildOverrides` / `ClearBuildOverrides` 钩子切换和清理驾驶显示。只调用 `AddOverrideBuild` 加入驾驶室符号并选择独立的 `aom_tractor_driver` bank，**不替换人物的 build**，所以人物自身、衣服、帽子和皮肤覆盖继续由原版维护。下车时原版恢复 `wilson` bank，只清理本 Mod 增加的覆盖。

原版骑牛动画来自多个 `player_mount*.zip`，bank 名为 `wilsonbeefalo`；bank 名并不代表一定存在同名 ZIP。构建脚本同时支持独立 `data/anim` 和 `data/databundles` 中的嵌套动画包，完整收集匹配的原版动作。

## 六向与遮挡

生成后的单一动画中按固定 Z 顺序组合：车尾挂件、座椅后景、原版人物、驾驶室前景、车头挂件。这样窗口、人物和车身使用同一动画、同一朝向，不通过异步跟随特效拼接。

前斜视、侧视、后斜视三种车体分别对应 `downside/side/upside`；保留原版 facing 位和左右镜像。构建过程保持原动作名称、帧数、帧率与帧事件，缩放人物矩阵并将原版待机头部锚点对齐到各方向驾驶室位置，保留原本的相对动作。

车身、车门和窗框位于人物前方，窗洞透明，驾驶室内壁/座椅在人物后方。收割机覆盖到车头符号，其他挂件覆盖到车尾。运行时换挂件也更新骑手上的符号。

## 构建产物与启用

- `AgeOfMachines/anim/aom_tractor_driver.zip`：包含驾驶室 build、图集和合成后的原版骑乘时间线。
- `AgeOfMachines/scripts/aom_driver_visual_bank.lua`：构建成功后写入 `available=true`。
- `Driver-Build-Report.json`：原版动画来源文件名和合成数量。

`Driver-Results.zip` 同时收集这些文件、日志与源工程清单。需要连同启用清单一起替换，并重启客户端和服务器；所有客户端使用同一版本。

当前仓库的启用清单为 `available=false`。Windows 成功前不会声明或加载尚不存在的驾驶动画包，现有功能仍可运行。编译成功不代替在游戏中检查座位位置、帽子遮挡、换向与上下车的视觉表现。

## 检查范围

新增测试执行真实原版上下车组件，确认切换驾驶 bank、保持角色/帽子 build、只清理本 Mod 覆盖、更新挂件，以及未编译/缺包时不启用。

二进制合成器对已编译 ANIM v4 做结构回读/写入校验，并检查原动作名、帧率、帧数、帧事件、六向选择、座位锚点、人物相对运动与前后层次。模拟完整 Windows 构建流程及独立/嵌套原版资源查找。

这些检查使用真实格式资源和可观察的引擎/角色动画测试夹具，不是实际游戏里所有人物皮肤与全部原版骑乘动画的视觉验收。Windows 原版资源合成和 DST 实机验证是后续验收步骤。
