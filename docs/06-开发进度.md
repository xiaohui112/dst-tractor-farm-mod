## 三、开发中修正掉的错误（记录备查）

| 问题 | 后果 | 修正 |
|---|---|---|
| `AOM_TAG` / `AOM_STRINGS` 在 prefab 环境不可见 | 加载即崩 | prefab 显式 `require("aom_common")` |
| `aom_common` 先挂 `GLOBAL.AOM_ATTACHMENT_TYPE` 再在本地引用 | nil 索引崩溃 | 先建局部表再挂 GLOBAL |
| 用 `Map:SetTile` 直接刷农田地皮 | 绕过原版，会毁掉地皮 | 改用 `terraformer:Terraform` |
| 以为有 `GetAimAngle()` | 运行时 nil 调用 | 改用 `_drive_angle` / `GetAngleToPoint` |
| 以为 `fuel` 组件有 `SetMaxFuel` | 运行时 nil 调用 | 油量改由 `net_float` 记录 |
| `TECH.ALCHEMY_TWO` | 配方注册失败 | 改为 `TECH.SCIENCE_ONE` / `TECH.SCIENCE_TWO` |
| 配方图标图集缺元素 | 制作菜单图标空白/报错 | 图集补全 7 个元素 |
| `modmain.lua` 直接调用 `pcall` / `Vector3` / `TheWorld` / `ActionHandler` | 加载即报 “attempt to call global 'pcall' (a nil value)”，整只 Mod 被游戏禁用（v0.1.1 实机日志） | modmain 跑在 `scripts/mods.lua` 的受限环境，只暴露白名单；改成 `GLOBAL.pcall` / `GLOBAL.Vector3` 或在文件头做 `local` 别名。自检新增 `check_mod_environment`，按白名单扫描 modmain，能复现报出这四处 |
| `aom_common.lua` 直接用 `GLOBAL` | `variable 'GLOBAL' is not declared`（v0.1.2 实机日志） | 脚本模块由 `require` 加载进游戏主环境，主环境没有 `GLOBAL` 这个名字；模块里改成 `local GLOBAL = rawget(_G, "GLOBAL") or _G`。自检新增 `check_script_modules` 扫描 scripts/ 下所有模块 |
| 模块里调用 `GetModConfigData(key)`、读取 `MOD_RPC` | 主环境的 `GetModConfigData` 必须显式传 modname（否则断言失败），`MOD_RPC` 只存在于 modmain 环境 | modmain 把选项与 RPC 句柄挂到 `GLOBAL.AOM_CONFIG` / `GLOBAL.AOM_RPC`，模块只读这两份；`check_script_modules` 一并拦截这两个名字 |
| `GLOBAL.containers.params` | `variable 'containers' is not declared`（v0.1.3 实机日志） | `containers` 是 `require("containers")` 返回的模块，不在 `_G` 里；改成 `require("containers").params`。自检增加 `GLOBAL_MODULE_NAMES` 拦截这类“模块当全局用” |
| `AddClassPostConstruct("widgets/playerhud")` | `module 'widgets/playerhud' not found`（v0.1.4 实机日志） | 当前版本 PlayerHud 在 `screens/playerhud.lua`，旧路径已不存在；改为 `screens/playerhud`。自检新增 `check_game_paths`：直接读本机 `data/databundles/scripts.zip`，核对所有 `require` 与 `AddClassPostConstruct` 路径 |

## 2026-11-11：实机加载失败修复（v0.1.1 → v0.1.2）

- 实机启动报 `../mods/AgeOfMachines/modmain.lua:33: attempt to call global 'pcall' (a nil value)`，游戏随即 `Disabling AgeOfMachines because it had an error`。
- 原因：modmain 不在全局环境执行。官方 `scripts/mods.lua` 的 `CreateEnvironment` 只给 `pairs/ipairs/print/math/table/type/string/tostring/require/Class/TUNING/GLOBAL/MODROOT` 等白名单，`modutil.InsertPostInitFunctions` 再补约 100 个 Mod API；`pcall`、`Vector3`、`TheWorld`、`ActionHandler` 都不在其中（prefab 文件由 `loadfile` 加载，仍是全局环境，不受影响）。
- 修正：文件头用 `local pcall = GLOBAL.pcall`、`local Vector3 = GLOBAL.Vector3`、`local ActionHandler = GLOBAL.ActionHandler`，`TheWorld` 改为 `GLOBAL.TheWorld`。
- 自检新增 `check_mod_environment()`：按上面的白名单扫描 `modmain.lua` / `modworldgenmain.lua`，把不在白名单、又没有 `local` 别名或 `GLOBAL.` 前缀的全局名连同行号报出来；已用旧版本文件验证能复现报出这四处。
- 同一轮实机日志还暴露了模块侧的两个问题：`aom_common.lua` 直接读 `GLOBAL`（主环境没有这个名字），以及模块里的 `GetModConfigData` / `MOD_RPC`（前者必须显式传 modname，后者只在 modmain 环境存在）。已改为 modmain 把 `GLOBAL.AOM_CONFIG`、`GLOBAL.AOM_RPC` 传给模块，并新增 `check_script_modules()` 扫描 `scripts/` 下的所有模块。版本 0.1.3。
- 随后实机又报出两处版本/环境问题：`GLOBAL.containers`（`containers` 是模块不是全局，改 `require("containers")`），以及 `AddClassPostConstruct("widgets/playerhud")`（当前版本 PlayerHud 已移到 `screens/playerhud`）。自检新增 `check_game_paths()`：读取本机 `data/databundles/scripts.zip`，逐一核对 Mod 里所有 `require` 与 `AddClassPostConstruct` 路径。版本 0.1.4 / 0.1.5。
