# 原版 FindEntities 的浮点边界

2026-11-16。仅分析与离线复现，本轮未修改 Mod。

## 结论与证据范围

本机原版 macOS x64 专用服务器（启动版本 762172）的普通 `TheSim:FindEntities` 路径：

1. `Transform:SetPosition` 将 Lua double 坐标转成 float32；`GetWorldPosition` 将 float32 转回 Lua double，不能恢复此前丢掉的精度。
2. `FindEntities` 将查询中心 x/y/z 和半径转成 float32。
3. 距离平方和半径平方均用 float32 运算，每次减、乘、加都有单精度舍入。距离包含 x/y/z 三个方向；地面农作物 y 相同时退化成 x/z。
4. 距离过滤只在 `distance_squared > radius_squared` 时排除候选。因此有限正常数值下，等于边界会通过；该距离过滤没有加 epsilon，也没有扩张实体物理半径。实体仍需满足有效性和标签等其他条件。

这些结论来自本机原版二进制调用链和指令，不是根据 Lua API 名称猜测。专用服独立世界实测尝试因磁盘不足中止，没有成功取得 FindEntities 返回列表；下文数字是按指令顺序复现的计算结果，不能冒充游戏内查询记录。其他平台、版本仍需分别核对。

## 用户指出的数值具体如何变化

输入 `a=8+4/3`、`b=4+4/3`，另一坐标相同：

| 阶段 | 结果 |
| --- | --- |
| Lua double 的 a | 9.333333333333334 |
| Lua double 的 b | 5.333333333333333 |
| 直接用 double 算距离平方 | 16.000000000000007，严格比较 16 会失败 |
| 引擎存储的 a | 9.333333015441895 |
| 引擎存储的 b | 5.333333492279053 |
| float32 坐标差 | 3.999999523162842 |
| float32 距离平方 | 15.999996185302734，比较 16 会通过 |

引擎并没有接收到 `16.000000000000007` 再对它做小数位四舍五入。它接收并存储坐标，再按单精度顺序重新计算距离。

另以中心 0、半径 4、另一个实体只沿 x 方向偏移为例：输入 `4.0000001` 会先存成 `4.0`，距离过滤通过；输入 `4.000000476837158` 仍大于 4，距离平方为 `16.000003814697266`，过滤失败。这是单精度量化，不是“所有接近 4 的数都算 4”的容差规则。

## 对当前离线场景的复核

保持原冻结快照不变，复核秋季 `square-3/all-40/GIANT` 的原坐标输入：

- 模拟原版 float32 距离后，相比旧 double 判定改变 36 条有向邻接（18 对）。
- 与该标准九宫格的整数索引数学基准相比，漏边 0，多边 0。
- 上一轮隔离实验输出的 81 株布局，同族数量检查全部通过 float32 复核。

该结论限定于这批原始坐标，未代表任意地图平移、任意实地偏移都等价于整数网格；也未重新进行整套求解测速。此前 0.533 秒是边界归一隔离实验耗时，不能标为完整原版 float32 模型的实测耗时。

修复方向应先对齐离线 Transform 与原版距离运算，再统一规划器各条距离判定路径并复跑对照。仅把输出显示成 16、任意加固定容差、或只将最终距离平方转 float32，都不能一般性保证与原版一致。

| 位置 | 证据 |
