# 0.5.20：补齐18株模版的配比覆盖

日期：2026-11-16。验证使用实际Mod Lua 5.1入口、游戏原版作物定义、独立检查和网页；未启动DST客户端进行生长或帧率验收。

## 根因

秋季两块横向地皮，大蒜、洋葱、辣椒各6颗，0.5.19自动选配只使用各4颗，返回12株；锁定`program-18-equal`则没有候选。原因是程序18株模版沿用了局部作物白名单：6＋6＋6仅收录部分弱养分组合，遗漏了强养分三作物；6＋12同样漏收洋葱／石榴与西瓜。不是库存不足，也不是在已有18株候选中主动选择12株。

原有测试只给两项程序扩展各测了一个正例。目录逐格校验只能证明已收录内容正确，无法发现应该支持但没有收录的组合。此次以原版作物规则独立枚举输入，再检查Mod能否给出18株，补上这项覆盖缺口。

## 修复

- 两项程序扩展在构建时枚举共同应季、不同作物、逐地皮养分净变化为零的全部原版配比，固定格子布局，逐格验证同族与坑距。相同需求只收录一个映射，先保留原有映射。运行时仍只读取预生成目录。
- 截图模版不允许启用这项扩展政策，原图OR范围和格子不变。修改前后的304项截图坐标用例完全一致；包括程序扩展在内共有364项坐标用例。
- 首轮扩展回归发现两个混合库存案例的数量回退：增加候选改变了有界搜索顺序。最终增加原候选独立选配作为保底，再比较完整方案；原候选的尝试计数与额度独立，不拼接两套库存结果。首轮中间数据保留在`outputs/template-18-coverage/intermediate-first-expansion`，未作为最终验收。
- 最优策略的最大合法数量证明、优先级、64块上限及排列流程未调整。网页继续直接调用Mod的目录、Build和Validate。

## 最终验证

| 验证 | 结果 |
|---|---|
| 独立枚举18株配比 | 四季共27组输入，横／纵、正负平移、L形及蛇形共162例全部返回18株；旧版有13组季节输入不能返回18株 |
| 库存边界 | 每个配比检查精确库存、每种多1颗、逐种少1颗；锁定完整18株模版时不足库存不得生成 |
| 模版完整回归 | 1162例全部合法，58例比旧版多播，其余数量相同，0回退 |
| 最优完整回归 | 1162例全部完成，0错误，数量逐例与0.5.19相同 |
| Mod自检 | 684项行为测试通过，0失败、0跳过；静态／资源检查通过，发布模式0警告 |
| 网页测试 | 21项通过，含两策略逐坑一致性及独立枚举18株配比 |
| 大田补充 | 四季应季各99颗×9／32边长共8例，加9×9强养分三作物库存1例，均完成且合法 |

大田模版是有界整块选配，不宣称证明全田最大数量。例如9×9地皮、大蒜／洋葱／辣椒各240颗，本轮返回696株，库存上界720未达到；不能将此次双地皮配比补齐说成任意大田必定达到库存上界。过去另行记录的最优大田慢例也不属于此次已解决问题。
