# 0.5.17 巨大化规划优化与日志验证

日期：2026-11-16。版本0.5.17。只在游戏内Lua执行，不增加外置运行程序；网页继续加载Mod原始Lua。保留“合法性 → 全田最大合法播种量证明 → 同族紧凑 → 整齐”的顺序，没有货仓槽位优先规则，也没有限时后降级播种。

## 实现与边界

- 完整数量证明保留调用栈，与通用可行构造交替推进。构造找到更好合法下界后共享给证明；只有达到安全上界或完成完整证明才返回。构造失败不等于全局无解。
- 大田新增多配比连续区域构造，局部精确搜索只提供候选，完整田必须重新校验；几何邻域以空间桶加速，并保留原始浮点距离判定。
- 世界共享分帧额度：前台约4毫秒、后台约1毫秒，每次最多1024次恢复。都是协作式软额度，单次长恢复不能强制抢占。
- 同一有效输入可暂停接续；最多保留4个暂停任务、8个完整方案缓存。规范化实际坑位、季节、有效库存、作物定义和约束。增加种子或改变现场也必须重新证明，不能仅凭旧布局仍合法复用。
- 骑乘空闲、挂载播种机、没有正式计划且目标田明确时，间隔2秒连续两次输入相同才低额度预计算。后台不扣物料、不自动开工；按F接续前复核，正式提交前再复核。只挂载但没有目标田时的组合预热尚未实现。
- 最大范围仍为64块。测试用81块覆盖实验中，秋/春/夏均未在30秒内完成，冬季完成；没有把测试覆盖开关作为生产扩容，也没有降低最大数量优先级。

## 日志用于实机复现

独立文件：`~/Documents/Klei/DoNotStarveTogether/tractor_giant_planning_master.log`，洞穴为`tractor_giant_planning_caves.log`。按同一车辆GUID与任务编号串联。

| 记录 | 分析用途 |
|---|---|
| START / RULES | 版本、源码指纹、调度额度及当时作物/距离/密度规则 |
| INPUT / PITS | 求解前保存库存、季节、完整真实坑位；异常退出时仍有输入线索 |
| STAGE_BEGIN / PROGRESS | 当前阶段、搜索方法、目标、最好合法数量、证明节点；进度每2秒写一次 |
| METHOD | 每条搜索路径的CPU与恢复次数，定位试探成本；不与数量总耗时相加 |
| STEP / SUMMARY | 数量/整齐分阶段CPU、墙钟、等待、切片分布、最长恢复、完成证明状态 |
| LAYOUT | 最终逐坑位作物，用于复现与比对 |
| FIRST_SEED | 本次F请求到首种的真实等待；后台接管时不把提前计算时间算作按键等待 |
| SOW_COMPLETE / SOW_STOPPED | 计划量、实际进度、消费汇总或中断原因 |

游戏原版毫秒时钟可用时记录毫秒精度；离线缺少该API时明确回退到秒级。CPU仅累计规划执行片段，但进程CPU仍可能包含引擎其他线程。没有将日志当作独立Lua线程CPU/GPU、客户端收包延迟或崩溃根因证明。
