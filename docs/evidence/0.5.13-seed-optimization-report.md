# 0.5.13 巨大化策略：最大合法数量与分阶段耗时

2026-11-15完成。运行源码、安装包与本机Mod均为0.5.13；87个运行文件逐字节一致。

原30个数量证明超时案例均在相同30秒墙钟上限内完成。完整1162例全部完成并通过独立校验：0超时、0非法布局、0数量回退。451例合法配比数量为零，均未误播。与优化前已完成的同规则案例相比，播种数量保持一致。

硬约束保持应季、库存、实际坑距与密度、逐株同族、逐地皮三类养分净变化为零；4＋4中心留空。先证明最大合法播种量，再保持数量做一次紧凑/整齐优化。

## 通用优化

1. 固定目标株数，联立总数量及两维净变化，直接解出最多三个作物数量；同属性库存按可整体改名覆盖的规范代表枚举。
2. 动态拆分互补库存，在实际小块地皮上求解、合并合法见证；另探测紧凑地皮子集。失败只表示构造未成功，不排除原目标或降低数量。
3. 结合有界逐坑探测、精确跨格计数传播、完整约束搜索、可恢复配额轮转与完整失败状态缓存。截断状态不会缓存成无解；每次恢复搜索前重建对应库存上下文。
4. 固定数量目标内优先尝试单格同族支持较多的配比，仅改变分支顺序。数量证明后才运行整齐优化，不交付“少播但更整齐”的计划。

没有种子名称、季节配方或地形专用答案；Python/SciPy只用于独立审计，不把求解结果注入Mod。网页直接加载相同Mod原始Lua5.1模块。

## 两阶段耗时（进程CPU秒）

数量阶段包括组合准备、可行见证构造和最大数量证明；排列阶段只包括证明完成后的同族紧凑、行列整理。全部场景同时保留端到端墙钟秒。审计使用4进程，同期还运行发布/网页检查；系统负载会影响单次时间。CPU秒不等同于游戏分帧等待。
