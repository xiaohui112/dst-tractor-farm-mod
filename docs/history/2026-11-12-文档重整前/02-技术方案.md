# 0.5.1 技术方案

本文描述当前架构。旧版“第一格放挂件”“建筑驾驶态”的方案保存在 [历史版本](history/02-技术方案.md)，不再作为实现依据。

## 实体与所有权

拖拉机是使用原版 Rideable/Rider 的世界实体；角色的原版移动、动作和承伤链路保留。配件也是独立世界实体，不具有 InventoryItem，通过独立挂点连接；九格 Container 只保存货物和物料。

服务端独占农业改动、材料消耗、挂卸、维修和计划确认权。客户端通过原版动作/RPC发出请求，只读取 netvar/replica。所有驾驶面板RPC校验当前骑手、幽灵/死亡和busy状态。

| 模块 | 职责 |
|---|---|
| `aom_equipment_defs` | 六类配件的耐久、维修量、速度、图标、物料和损坏原因 |
| `aom_attachment_mount` | 独立挂点、权限/距离、落点、实体跟随和保存恢复 |
| `aom_drive` | F开关、经过地块、工序分发和统一消耗结算 |
| `aom_work_result` | 一次结算单位的实际改动、完成情况、原因和异常 |
| `aom_work_status` | 稳定原因码、参数及本地化显示，不用提示文字判断业务 |
| `aom_farm_work` | 原版铺地、坑位、种植、DIG、Pick及巨大产物HAMMER适配 |
| `aom_irrigator` / `aom_fertilizer` | 按实时水肥缺口完成整格工序和物料消耗 |
| `aom_block_plan` | 经过约束验证的固定配比、预览/旋转/确认、坐标进度和迁移 |
| `aom_plan_preview` | 客户端本地绿色坑位与下一地块标记，没有农业组件、网络或存档 |
| `aom_attachment_animation` | 服务端驱动配件工作状态及成功后的短时特效 |

## 作业与结算契约

配件是否能继续作业统一调用`aom_durability.CanWork`，规则数据留在`aom_equipment_defs`，不将行为回调塞入配置表。

内部结果统一表达 `changed`、`complete`、`reason`、`position`、`error`。兼容入口 WorkHere 统一返回 `changed, reason, complete`；WorkTile负责燃料，WorkHere负责底盘/配件耐久。播种每颗结算，其他设备每个实际改动地块结算一次。仅拾取不计费。

工序执行前统一检查车体、底盘和实际配件机械耐久。洒水机水量与机械耐久分别保存，施肥机的机械耐久与仓库肥料分别保存；卸载受阻时保留配件但仍禁止零耐久工作。

原版回调可能先改动实体、再抛错。Observe在成功或异常后检查土坑、工作量、植物状态及产物，Run统一捕获异常。底盘、配件耐久和展示回调分别保护；一个结算回调失败不跳过其他结算，展示失败不会免单，错误返回WorkTile后按实际改动扣油并停工。临时库存/掉落方法、配件结算归属和NOBLOCK标签都会恢复。详细异常留在服务端日志，HUD只显示可操作提示。

Pickable在生成产物后才调用onpickedfn。若已产出而回调失败，将该次采摘记录为原版picked状态，防止重试/读档复制产物；保留现场等待检查，不重新生成或删除掉落。

开垦、除草、收割共用拾取规则，并追踪本次回调的新掉落，允许收纳散到格边外的本次产物，不扫描拾取邻格原有物品。新田随机杂物如果会破坏邻格土坑，则跳过该次生成位置。

## 计划与存档

配比先预览、旋转和确认，再按F开工。计划绑定起始地块、方向、布局ID和已种坑位。预览不改地、不消耗资源；确认时重验季节、场地、种子和模板。逐坑仍检查现场，不能用预览替代真实作业校验。

GetTargets只接受明确确认的计划，不创建/重置计划；完成后保留全套坐标和进度，下一轮必须显式重规划和确认。NEXT_TILE是两类设备共有的非停机提示。预览失败优先报告可用模板的场地原因，其次报告材料足够模板的验证原因，只有没有足够材料时才报告缺种。

v3模板必须通过当前世界挖坑间距、跨格距离、逐格养分、季节、拥挤和逐株家族条件。全部109条可自动布局已重算，2条养分不平衡分支仅供参考。

计划使用v3存档。旧v2坐标和索引不套用到新模板，保留作物和货物，标记待重规划；不会静默搬动或重种。旧打包车先找到落点再移出原库存，没有落点时保留原归属、提示一次并每5秒重试；待迁移状态可再次存档。

## 同步与资源

停机原因由一个`_workstate_net`字符串携带原因码及参数，按首个`|`分隔，通过`aom_work_status.Read`读取完整快照；各客户端独立翻译，业务不直接比较载荷。其余同组netvar可共用dirty事件，监听者将事件视为整组失效并重读，不能将跨字段当成原子快照。客户端与服务端需使用相同版本。

计划同步布局ID、坐标、方向、确认状态、成功索引和下一地块，客户端通过相同模板还原预览，不反序列化可执行代码。

四档驾驶bank保留原动作、朝向、帧事件及人物比例补偿，共享 `aom_tractor_cabin.zip` 中的build与贴图，每个驾驶ZIP仅保存自身动画。只加载共享包及当前选中的bank；资源优化逐字节核对anim.bin不变。详见[美术接入](08-美术接入.md)。

## 洒水职责与音频

`aom_irrigator.WaterTile`根据实时缺口循环补满并扣水；`aom_soil_moisture`读取原版网格、应用一剂并验证效果；`aom_farm_work.Water`仅为旧DoWork入口提供转发。网格读取失败安全停工。洒水与施肥先判定是否需要处理，再由各自模块校验燃料，成功整格只扣一次油和机械耐久。

源音频在`assets/audio`，游戏加载的FEV/FSB在`mod/Tractor/sound`，配置和打包均验证实际运行资源。

## 验证边界

发布打包必须运行 `selfcheck.py --release`：缺少Lua依赖、失败、警告或跳过都会阻止生成安装包。报告分别记录每项检查及执行/跳过数量，识别macOS应用包、Windows和Linux Steam目录。

行为测试执行原版组件和地图邻坑破坏逻辑，但引擎图形、输入分发和真实网络仍有桩。预览画面、角色皮肤、多人同步与声音必须另做DST实机验收，不能以自动测试代替。
