# 驾驶室坐姿接入

> 以下记录旧版三视图接入过程。0.2.3 保留这里核验过的人物时间线，并重建五视图、八向与行驶图层；当前源文件和命令见[六项修复说明](16-比例方向仓库卸载行驶与九宫格修复.md)。

已接入用户提供的 `Driver-Results.zip`，启用复用原版骑牛坐姿的驾驶显示。Windows 产物包含 331 条原版时间线合成的 1,217 个朝向变体、38,004 帧及两张 KTEX 图集；本机尚无最终游戏内画面的实机验证。

当前安装包已包含驾驶动画，无需再次编译。下方 Windows 操作用于今后重建。

## Windows 操作

下载 `AgeOfMachines-Windows-Driver-Kit.zip`，完整解压到英文短路径，例如 `C:\AOM-Driver\`。

1. 双击 `Build-Driver.cmd`。
2. 如提示，选择完整 Mod Tools 目录中的 `scml.exe`。
3. 如提示，选择饥荒联机版安装根目录（包含 `data` 的目录）。
4. 成功后发回 `Driver-Results.zip`，不要只发一个动画 ZIP。

脚本使用 Mod Tools 自带 Python 2.7，也兼容 Python 3 标准库；不需要图像生成工具或额外 Python 包。包内中文说明包含故障处理。

## 动作与角色外观

上车仍由原版 `ACTIONS.MOUNT` / `Rider:Mount` 执行，下车由原版 `ACTIONS.DISMOUNT` / `ActualDismount` 执行。没有替换原版 rider 组件或角色状态机。

拖拉机通过原版 `ApplyBuildOverrides` / `ClearBuildOverrides` 钩子切换和清理驾驶显示。只调用 `AddOverrideBuild` 加入驾驶室符号并选择独立的 `aom_tractor_driver` bank，**不替换人物的 build**，所以人物自身、衣服、帽子和皮肤覆盖继续由原版维护。下车时原版恢复 `wilson` bank，只清理本 Mod 增加的覆盖。

原版骑牛动画来自多个 `player_mount*.zip`，bank 名为 `wilsonbeefalo`；bank 名并不代表一定存在同名 ZIP。构建脚本同时支持独立 `data/anim` 和 `data/databundles` 中的嵌套动画包，完整收集匹配的原版动作。

## 六向与遮挡

生成后的单一动画中按固定 Z 顺序组合：车尾挂件、座椅后景、原版人物、驾驶室前景、车头挂件。这样窗口、人物和车身使用同一动画、同一朝向，不通过异步跟随特效拼接。

前斜视、侧视、后斜视三种车体分别对应 `downside/side/upside`；保留原版 facing 位和左右镜像。构建过程保持原动作名称、帧数、帧率与帧事件，缩放人物矩阵并将原版待机头部锚点对齐到各方向驾驶室位置，保留原本的相对动作。

车身、车门和窗框位于人物前方，窗洞透明，驾驶室内壁/座椅在人物后方。收割机覆盖到车头符号，其他挂件覆盖到车尾。运行时换挂件也更新骑手上的符号。

## 构建产物与启用

- `Tractor/anim/aom_tractor_driver.zip`：包含驾驶室 build、图集和合成后的原版骑乘时间线。
- `Tractor/scripts/aom_driver_visual_bank.lua`：构建成功后写入 `available=true`。
- `Tractor/Driver-Build-Report.json`：原版动画来源文件名、合成数量和被忽略的重复动画。

`Driver-Results.zip` 同时收集这些文件、日志与源工程清单。需要连同启用清单一起替换，并重启客户端和服务器；所有客户端使用同一版本。

2026-11-11 已在本机 Windows 完成编译并接入：`aom_tractor_driver.zip` 23.1 MiB，1217 条动画（来自 331 条原版骑乘时间线），启用清单为 `available=true`，安装包与游戏 mods 目录同步更新。接入使用 `python tools/apply_driver_results.py`：先校验 ZIP CRC、BILD/ANIM/KTEX 签名、bank/build 名称和 `mount`/`dismount`/`idle_loop`/`run_pre`/`run_loop`/`run_pst`，全部通过才覆盖现有文件，校验失败不动任何现有文件。

当前构建记录中被忽略的重复原版动画为 `wilsonbeefalo/255`、`x/255`、`xxx/255`（多个 `player_mount_*.zip` 各自携带的 bank 名占位动画）；没有人物层的原版状态帧为 `sink` 与 `slingshot_powerup` 的若干朝向，这些帧保留驾驶室图层而不是中断整次合成。

启用清单为 `available=true` 而动画包缺失时，`aom_driver_visual.Configure` 会回退原版骑乘显示，但 `tools/selfcheck.py` 会直接报错，打包前必须先跑自检。

重建工具包仍从 `available=false` 开始，成功生成资源后才启用。编译成功不代替在游戏中检查座位位置、帽子遮挡、换向与上下车的视觉表现。

## 检查范围

新增测试执行真实原版上下车组件，确认切换驾驶 bank、保持角色/帽子 build、只清理本 Mod 覆盖、更新挂件，以及未编译/缺包时不启用。

二进制合成器对已编译 ANIM v4 做结构回读/写入校验，并检查原动作名、帧率、帧数、帧事件、六向选择、座位锚点、人物相对运动与前后层次。模拟完整 Windows 构建流程及独立/嵌套原版资源查找。

这些检查使用真实格式资源和可观察的引擎/角色动画测试夹具，不是实际游戏里所有人物皮肤与全部原版骑乘动画的视觉验收。Windows 原版资源合成已完成，DST 实机验证仍是后续验收步骤。

## 本次产物核验

结果包来自提交 `2337907`，外层 ZIP 的 Git blob SHA 与 GitHub 一致，内外 ZIP CRC 通过。实际解码确认 ANIM v4、BILD v6、两个 KTEX 图集、四个驾驶室/挂件符号、唯一的动作/朝向组合，以及六向上下车、待机和行驶动作。矩阵数值有限，动作保留原版帧率。

源清单中 SCML 和六张车体 PNG 的 SHA-256 与仓库一致。两个透明挂件占位 PNG 的哈希不同；已用 krane 反解编译后符号，确认它们均为 256×256 且 alpha 最小值、最大值均为 0，与本地占位图完全透明的用途一致。未把源文件差异误记为全部哈希相同。

Windows 报告记录了重复占位动作去重，以及 `sink`、`slingshot_powerup` 个别原版空人物帧；这些报告已保留。编译器源码的原版兼容处理是否能完整复现本次结果，仍需携带 Windows 使用的构建脚本再次核对。

构建报告、来源清单、资源 SHA-256 和核验边界保存在 `assets/driver/build/windows-2026-11-11/`。
