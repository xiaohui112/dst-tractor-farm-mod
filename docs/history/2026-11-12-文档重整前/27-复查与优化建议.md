# 0.5.1 复查结论、误判纠正与修复

本文替换DSH对0.5.0的初始复查结论。原报告的“25个Lua文件”统计不准确，运行目录`mod/Tractor`实际包含40个Lua文件（含modmain/modinfo）。0.5.0自动回归基线为375项；本次新增11项并加强跨轮流程，总计386项。自动测试使用真实Lua模块和原版组件，但图形、输入与网络仍有引擎桩，不能据此声称实机验收完成。

## 已确认的4个问题及修复

| 问题 | 原因 | 0.5.1处理 | 回归证据 |
|---|---|---|---|
| P1：收获后隐式更换配比、起点与方向，并绕过确认 | GetTargets在空田重置计划并递归创建；新计划confirmed缺省值可通过false检查 | 作业入口只接受confirmed为true的现有计划，不创建/重置。完成后保留原计划和索引；下一轮必须在播种面板显式重规划、预览并确认 | 完成后驶到40单位外、换可用种子、保留旋转及存档恢复均不改变原计划；明确确认后才施工；两轮完整开垦/播种及收获残渣保护 |
| P2：成功特效或耐久回调异常跳过结算、停工 | PerformWork受保护，但后续特效及底盘/配件Use在保护范围外 | 底盘、配件、特效和底盘动画分别捕获异常；按实际改动结算，WorkTile扣油并停机。停止动画失败不阻止取消采样；临时配件结算归属必清理 | 特效异常、底盘回调、配件回调、两者同时异常、停止动画异常；实际产物保留、每项扣费一次、采样停止、重试不重复产出 |
| P2：NEXT_TILE让开垦机误停，播种机却继续 | 两条分支的complete返回值不一致 | GiantWorkHere统一将NEXT_TILE视为可继续行驶的提示 | 两种设备驶出计划区均零改动/零消耗并保持开工，驶回目标格继续工作 |
| P2：模板校验失败误报缺种 | Preview丢弃ValidateCombo的失败原因 | 分开记录材料不足、模板错误和场地错误；可用模板的场地错误优先，其次是有足够种子的模板错误 | 改坑距返回MOUNDS_TOO_CLOSE，地形不可用返回INVALID_LAND，库存不足返回MISSING_SEEDS；失败旋转保留原预览 |

主要实现：`aom_block_plan.lua`、`aom_drive.lua`、`aom_work_result.lua`、`aom_durability.lua`。新增回归：`tools/tests/test_review_regressions.py`；原有`test_giant_farming.py`和`test_landclearer_flow.py`的跨轮测试已改为明确预览/确认，而不是保留有缺陷的自动重置预期。

确认字段缺省时按未确认处理；正常0.5.0的v3保存已写明confirmed，继续保留。旧v2布局仍安全停用，不迁移旧坑位索引。

## 对DSH原8项结论的逐项纠正

| 原编号 / 主张 | 核对结论 | 源码与证据 / 本次处理 |
|---|---|---|
| 1：洒水/施肥免燃料、可扣成负数（P0） | **误判** | `aom_irrigator.WaterTile`和`aom_fertilizer.WorkTile`在需要处理时各自检查燃料；`ConsumeFuel`不足时拒绝，`SetFuel`下限为0。成功整格扣1油；零油不动土壤、不耗水肥。保留现有按需检查，不盲删豁免条件 |
| 2：多个netvar共用dirty事件必有一致性问题（P1） | **未成立** | 原版`rock_ice.lua`的_ismelt与_stage同样共用stagedirty；共享事件表示整组失效，监听者重读整组。共享事件本身不能证明丢更新，拆事件也不提供跨字段原子性。已补充组事件契约，保留合理分组 |
| 3：workdetail/workreason必然错位（P1） | **未复现；有设计改进价值** | 原报告对两次Set、dirty触发及客户端处理先后的推断缺少真实网络证据。本次主动合成一个`_workstate_net`载荷，原因与参数一起发布、由Status.Read/Describe读取；不再依赖跨netvar快照。即时订阅测试每次更新均拿到完整配对 |
| 4：洒水仅一剂、需要将limit改为4（P1） | **误判；旧注释确需修正** | 补满循环在`aom_irrigator.WaterTile`的for循环中。驾驶层limit=1表示一整格工序；外层改4可能破坏结算单位。保留单格调用，修正`aom_farm_work.Water`的过期注释 |
| 5：没有FSB，音乐素材未接入（P1） | **误判** | `assets/audio`是源素材；游戏加载`mod/Tractor/sound/aom_irrigator_music.fev`及`.fsb`。配置清单available=true，Configure注册两项Asset；测试核对RIFF/FSB5、事件/音频内容及安装包一致性。资源已接入，实际听感仍待游戏内验证 |
| 6：WorkTile设备检查重复、职责偏重（P2） | **有效维护建议，已优化** | 移除驾驶层按开垦/除草/收割/播种逐个重复的耐久判断，前置和继续检查都走`aom_durability.CanWork`。定义表保留纯数据，作业逻辑保留各自模块；燃料和材料按原有规则统一结算 |
| 7：文档11、14编号重复（P2） | **存在，已修复** | 行驶速度依据改为[28号](28-行驶作业与速度依据.md)，旧驾驶室接入改为[29号](29-驾驶室坐姿接入.md)；11号/14号分别保留开垦/施肥规范。同步当前索引、源码注释及历史文档引用 |
| 8：三个洒水模块存在重复实现（P2） | **没有重复算法；职责说明可改善，已完成** | Irrigator编排整格和水箱；SoilMoisture读取网格并验证一剂；FarmWork.Water只转发兼容调用。技术方案与源码注明边界，避免再次误认为驾驶层少了循环 |

`debug.getupvalue`读取原版水分网格是兼容性约束；读不到时返回MOISTURE_UNAVAILABLE并停工，已有回归覆盖。不能仅据此断言当前功能不可用。其他Mod或游戏更新后的实机兼容性仍需单独验收。

## 定向验证结果

- 洒水：从0到100用4剂水，整格仅扣1油、1底盘耐久和1机械耐久；零油时水量与水分不变。
- 施肥：按原版肥料效果补三类养分，整格仅扣1油及一次耐久；零油时养分与库存不变。
- 音乐：FEV/FSB资源、事件名、原始PCM与运行包核对；资源存在不代表已完成真实客户端试听。
- 状态：EMPTY/irrigator、FERTILIZER_MISSING/13、CARGO_FULL和清空依次只发布一个完整载荷；不同语言客户端读取同一数据，各自翻译。

对应原有测试：`test_irrigator_flow.py`、`test_fertilizer_flow.py`、`test_irrigator_music.py`。本轮新增11项见`test_review_regressions.py`，完整回归386项。

## 自检与打包

发布必须通过`tools/package_mod.py`内置的`selfcheck.py --release`，要求0失败、0警告、0跳过。安装包`Tractor.zip`生成后核对ZIP CRC、重复条目、全部64个运行文件与清单SHA-256及源文件字节一致。

最终结果记录在`outputs/selfcheck-validation.json`和`outputs/install-validation.json`，操作方法及实机边界见[发布验证](15-完整流程与发布验证.md)。本次仅更新项目安装包，未覆盖游戏mods目录；联机双方和专服更新时须使用相同0.5.1版本。
