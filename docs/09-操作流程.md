# 操作流程（与代码严格一致）

> 本文件描述**当前代码实际实现**的操作，任何动作分支都能在代码里找到对应。
> 最后核对：本轮修改后。

## 一、完整流程

### 1. 制造与放置
炼金引擎制作「拖拉机（打包）」、科学机器制作六种挂件 → 右键地面放下 → 变成拖拉机本体。

放置预览与服务端校验都对齐到地块中心，障碍或不可放置地块会拒绝，打包物品保留。放置使用原版 `DEPLOYMODE.CUSTOM`。

### 2. 手动连接挂件（必须手动）
- 打开拖拉机容器，把挂件放到**第1格**；第2～9格为种子、肥料物料格
- 挂件进入车上第 1 格槽位，车身显示对应挂件
- 没装挂件时车不能作业

### 3. 填充消耗品
| 挂件 | 要填什么 | 怎么填 |
|---|---|---|
| 播种机 | 种子 | 手持种子**右键拖拉机** |
| 施肥机 | 肥料（按剩余可施用次数统计） | 手持肥料**右键拖拉机** |
| 洒水机 | 水（新造为空，默认容量40次水壶用量） | 手持装满的水壶或冰块**右键拖拉机** |
| 开垦机 / 除草机 / 收割机 | 不需要 | — |
| 全部 | 燃料 | 手持木炭等燃料**右键拖拉机** |

只接收可燃型燃料。每次加油消耗一份，剩余堆叠保留；油量最高800，超出容量部分不返还，已经满油不扣材料。加油、装料、维修均需下车操作。

### 4. 上下车（沿用原版骑牛）
**右键拖拉机 → 原版「骑乘」动作上车**，提示文字使用游戏当前语言。驾驶座无需牛鞍或驯化。

**骑乘中右键自己 → 原版「下坐骑」动作下车**。若车上容器仍打开，原版优先提供关闭容器动作，关闭后再次右键自己下车。

上下车分别由原版 `ACTIONS.MOUNT` / `ACTIONS.DISMOUNT` 执行，保留原版动画、客户端预测和动作检查。不再提供 `Shift+F` / `Ctrl+F` 自定义上下车快捷键。

### 5. 作业（F 开关）
- 每次上车**默认关闭作业**，按 **F** 开启，再按 F 关闭。
- 点击下车时立即关闭作业；下次上车仍需按 F 开启。
- 驾驶时 F 不再触发原版攻击；步行时仍保留原版 F 行为。聊天、菜单、暂停时不会切换作业。
- 安装播种机后，左上角面板保留「切换播种策略」按钮；切换策略会停止作业，确认后按 F 重新开启。
- 换挂件、没油、缺料、配比条件不满足时停止作业，按提示处理后按 F 继续。

## 二、驶过地块完成一趟

车辆每0.1秒采样位置，但**不按时间重复作业**。开启后处理起始格一次，此后只处理新驶入的地块；两次采样之间跨过多格时补齐经过的地块。停车不反复扣料，离开再驶入同一格算新一趟。传送等大跨度位置变化不会沿线作业。

| 工序 | 驶过一格完成什么 |
|---|---|
| 开垦 | 铺农田后按原版规则生成杂物，自动铲除并保留原版概率掉落；确认清完后普通模式整理9坑，配比模式按计划整理 |
| 普通播种 | 一次种完本格空坑，每坑消耗一颗种子，无需停车等逐颗播种 |
| 配比播种 | 一次完成本格全部计划坑位，保留布局空位；全部计划地块仍须先准备好 |
| 浇水 | 读取实时水分，按原版每剂25按需浇满100；干地最多4剂，已满不消耗 |
| 施肥 | 按实时缺口选择有效肥料，沿用原版每份用量，补齐三类养分至各100；缺少对应肥料时保留进度并暂停 |
| 除草 | 仅铲本格允许 DIG 的杂草和园艺残渣，保护作物及土坑；清理后复查，未完成则暂停 |
| 收割 | 采摘本格成熟作物，并沿用原版HAMMER拆开巨大产物；不越界处理邻格 |

种子或燃料不足时，已完成的坑位保留，停止继续播种；补充后按 F 处理剩余空坑。失败种子退回，不凭空计数。燃料、底盘耐久仍按实际成功的原版动作结算：例如一格种9颗种子扣9次，停车采样不扣。洒水、施肥按单格结算：实际增加水分或养分时，无论用了几份，只扣1燃料和1底盘耐久；缺料保留进度并停机，补料后按F续作。

底盘耐久1000次，归零后停止作业；每个齿轮恢复100次，上限1000。播种机耐久100次，每成功播下一颗种子扣1次，失败不扣；耗尽保留挂件和未播种的种子，下车每份燧石恢复10次，上限100。普通播种覆盖本格四角土坑，不播邻格。修复后按F继续，最后一次耐久不会继续透支到下一个动作或地块。

作业开启时按挂件限速：犁地约54%、除草与收割约71%、播种约79%、洒水约93%、施肥100%，百分比相对空驶速度。关闭作业恢复空驶速度。现实参考与游戏尺度见 [11-行驶作业与速度依据.md](11-行驶作业与速度依据.md)。

开垦机实际处理过当前格，且车辆继续在该格移动时，烟筒位置持续产生小黑烟；停车、关闭作业、下车、换挂件或驶入不需耕作的地块后停止产生。世界物体与挂件动画已编译接入；烟筒锚点使用车头上方位置，仍需结合骑乘显示在实机微调。

开垦机耐久为60次，耗尽保留物品并停工；下车手持燧石右键拖拉机，每份恢复10次，满耐久不消耗。发生实际开垦改动时扣1燃料、1底盘耐久和1挂件耐久；部分完成会结算本次实际作业并暂停，未发生改动不扣。已有农田与重试不重复生成杂物。已有作物或建筑会被保护，杂物未清完不重排旧坑。旧 `aom_plow` 物品仍可读档和使用。详见[开垦机实现与验证](11-开垦机实现方案.md)。

除草机耐久为50次，每格发生实际清理时扣1燃料、1底盘耐久和1除草机耐久，无论该格清理几株；空地、预检失败或工作量未减少时不扣。耗尽保留挂件并停工，下车手持燧石右键拖拉机，每份恢复10次，上限50次，满耐久不消耗材料。杂草/残渣须具有允许工作的 DIG 组件；农作物即使带有 `weed` 标签或杂草名称也会优先被保护。作业回调之后重新检查后续目标和本格残留，部分完成会结算实际进度并暂停，排除原因后按F续作，不改动土坑布局。杂物掉落继续由原版回调处理。

除草回归位于 `tools/tests/test_weeder_flow.py`，覆盖原版 Workable/FiniteUses 和园艺残渣掉落、四种杂草名称匹配、邻格隔离、作物误标签保护、非DIG/禁用目标、清理失败及续作、耐久耗尽、存读档和停车；维修提示及材料扣除由 `test_native_riding.py` 验证。杂草实体与引擎地图使用测试桩，仍需DST实机及联机验收。

收割机一趟完成本格普通作物采摘与巨大作物拆分：先调用原版 `pickable:Pick`，新生成的巨大产物继续调用原版 `workable:WorkedBy` 的HAMMER路径；本格已经落地的新鲜/腐烂巨大产物也一并处理，蔬菜、种子与腐烂掉落沿用各自产物的回调。打蜡装饰、其他玩家或驾驶员原本持有的巨大物件、未成熟植株、杂草和建筑均不处理。普通采摘的背包/落地规则沿用原版，锤开后的产物按原版落地。只有本次采摘新生成并进入驾驶员库存的巨大产物会落回原株位置再拆分。每格有实际作业时合计扣1燃料、1底盘耐久和1收割机耐久，未发生变化不扣；部分完成也只结算一次并暂停，处理原因后按F续作。

收割机挂件耐久为40次，普通采摘与巨大作物拆分共用整格结算，不按株数或锤击次数重复扣除。最后一次耐久可完成当前格，随后停工并提示；耗尽保留挂件，不能继续收割后续地块。下车手持燧石右键拖拉机，每份恢复10次，上限40次，满耐久不扣材料；修复后按F继续。耐久沿用原版FiniteUses存读档。回归覆盖耐久耗尽、跨格停工、部分作业、空地不扣、满/损耗/耗尽读档及维修材料扣除。

原版杂草也带 `farm_plant` 标签，不能单凭此标签判定作物。现在共享识别优先看作物的 `farmplantstress`/`plant_def` 与杂草的 `weed_def`/`weedplantstress`，收割不采摘杂草，除草不会再把原版杂草误判为受保护作物。`tools/tests/test_harvester_flow.py` 执行原版Pickable、Workable及巨大作物掉落函数，覆盖14种作物、整格9株巨大作物、随机掉落、邻格保护、失败停机与续作；引擎、库存和植物实体使用测试桩，仍需实机与联机验收。

## 三、驾驶状态面板

骑上车后，屏幕左上角显示：

```
==== 拖拉机 ====
挂件：开垦机   燃料 400/800   车速 100%
作业中（F 关闭） / 作业关闭（F 开启）
种子/水箱/肥料余量（按当前挂件显示）
底盘 1000/1000   挂件耐久 60/60
配比进度（按当前策略显示）
［切换播种策略］（仅播种机）
```

停机原因会直接显示（没油、没挂件）。

面板、按钮、装料反馈、配比名称及停机原因均支持中英文。耐久和余量由服务端同步，客户端不访问服务端组件。

洒水机另显示「水箱 余量/容量 次水壶用量」。普通或高级水壶每1次余量转入水箱1次；冰块每次拆一份补1次；满箱不扣来源物品。旧存档余水按40次容量限制，旧版省略余量的满罐恢复为40次。

音乐已包含真实FMOD音频包并默认开启：洒水作业开启且有水时循环播放《兰花草》，停机、缺水、下车或离开范围后停止，可在Mod配置关闭。音乐异常不会影响洒水。音频构建和完整验证说明见 [洒水机实现与验证](12-洒水机实现方案.md)。

施肥机面板显示剩余可施用次数及前3种肥料库存。多次用量肥料留仓扣次数，最后一次返空瓶沿用原版；已满农田不消耗，不会给附近浆果丛等植物抢先施肥。装料按可接纳容量正确转移归属，失败退回。详见[施肥机实现与验证](14-施肥机实现与验证.md)。

## 四、代码对应

| 操作 | 动作 | 实现 |
|---|---|---|
| 上车 | 原版 `MOUNT` | 原版 `rideable` 场景动作 → `ACTIONS.MOUNT.fn` → `Rider:Mount` |
| 下车 | 原版 `DISMOUNT` | 原版 `rider` 场景动作 → `Rider:Dismount` → 原版角色状态机完成 `ActualDismount` |
| 作业开关 | F → RPC `AOM_TOGGLE_WORK` | 校验当前骑手后调用 `aom_drive.lua: ToggleWorking` |
| 播种策略 | 面板 RPC `AOM_SEED_MODE` | 校验当前骑手后调用 `CycleSeedStrategy` |
| 挂载挂件 | 容器第 1 格 | `itemtestfn` 只收 `aom_attachment` |
| 装料 | `AOM_LOAD` | 手持种子/肥料/水壶右键 |
| 加油 / 修理 | `AOM_REFUEL` / `AOM_REPAIR` | 燧石右键修已安装开垦机，齿轮修底盘 |

**状态图**：上下车直接使用原版 `SGwilson / SGwilson_client`。`wilsonbeefalo` 是角色动画 bank，不是单独的骑乘状态图。底盘的 `SGaom_tractor` 提供原版下车流程需要的 `idle` 状态。

**原版组件接入**：底盘保持可点击，`rideable.canride` 随燃料更新；座位占用、死亡等由原版上车动作检查。`rideable.shouldsave=true`，让原版角色存档包含正在骑乘的车辆。

**回归验证**：`tools/tests/test_native_riding.py` 执行原版 `rider / rideable` 组件和上下坐骑动作，检查提示、完整上下车、下车停工、占位、缺油、容器优先关闭、F 输入、速度同步和播种策略按钮等。引擎与控件使用桩，不能替代实机验收。

## 五、打包、存档和损毁

锤击健康车体可打包搬家，保持挂件及物料的原槽位、堆叠、剩余用量、油量、底盘耐久、血量和配比绝对坐标进度；重新放置不会恢复成满血新车。异地放置保留原规划，不会把已种作物的计划坐标自动搬走。

生命值降到0时停止作业并强制下车，掉落全部挂件与物料、禁止再次锤击打包，播放死亡动画后移除车体。不会生成另一台新车。旧版死亡存档恢复后也会回收容器内容，避免组件加载顺序导致物料丢失。

世界、挂件与驾驶室动画均已接入。仍需在真实DST客户端和专用服务器验证画面、联机预测、掉线重连与洞穴切换；自动化流程测试的范围见[发布验证](15-完整流程与发布验证.md)。

## 六、暂时不做的事

- **自动驾驶已移除**：原实现每 0.1 秒直接改坐标、只查地形不查建筑，风险高。等手动流程跑顺再考虑。
- **未实现的配置项已从菜单移除**：驾驶速度、普通地皮可翻、收获进背包、巨大化作物保留、调试日志。菜单现有「语言」和「洒水机音乐」。


## 配比播种修复版（2026-11-11）

巨大化模式不再按连续株数跨格拼配比。当前使用方法与限制以 [10-巨大化配比.md](10-巨大化配比.md) 为准：装齐种子 → 切换配比 → 换开垦机准备全部相邻地块 → 换播种机按固定坑位种植。第1格为挂件，第2～9格为物料；HUD增加布局进度与暂停原因。只有本格作业实际成功才扣作业燃料。
