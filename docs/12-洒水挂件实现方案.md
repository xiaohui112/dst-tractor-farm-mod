# 洒水机实现与验证

本轮已修复补水入口、水量单位、出厂空罐、旧存档迁移、按需浇满和消耗结算。显示名为「拖拉机洒水机」，保留 `aom_irrigator` prefab 与 `irrigator` 类型，兼容已有物品。

## 使用流程

1. 把洒水机放到拖拉机第 1 格。新制造的水箱为空，容量读取原版 `TUNING.WATERINGCAN_USES`，默认 40 次水壶用量。
2. 下车，手持普通水壶、高级水壶或冰块，右键拖拉机选择「装料」。普通/高级水壶按实际可转入次数补水，满箱不消耗水壶；冰块每次只消耗一份，不删除整堆。
3. 右键拖拉机上车，作业默认关闭。按 F 开启，用移动键驶过农田。开启时先处理起始地块，然后只处理新驶入地块；停车不重复消耗。
4. 水箱耗尽自动关闭作业。缺水时已增加的土壤水分保留，补水后重新按 F，仅补剩余差额。
5. 面板显示水箱当前余量/容量。换罐、卸下、保存读档都保留挂件自己的余水；更换同类水箱也会关闭作业。

## 单位与结算

水箱统一记录「普通水壶用量次数」，不是土壤水分点数。原版普通/高级水壶每次均补 25 点土壤水分，高级水壶的区别是自身容量更大。

| 情形 | 水箱消耗 | 燃料 | 底盘耐久 |
|---|---:|---:|---:|
| 干燥农田 0 → 100 | 4 次 | 1 | 1 |
| 农田 62 → 100 | 2 次 | 1 | 1 |
| 农田 99 → 100 | 1 次 | 1 | 1 |
| 已满农田 / 非农田 / 停车采样 | 0 | 0 | 0 |
| 仅有 2 次水，0 → 50 后缺水 | 2 次并停机 | 1 | 1 |
| 无水、无油、查询失败，未发生浇水 | 0 | 0 | 0 |

每次加水仍调用原版 `farming_manager:AddSoilMoistureAtPoint`，单剂水量读取 `TUNING.WATERINGCAN_WATER_AMOUNT`，目标读取 `TUNING.SOIL_MAX_MOISTURE_VALUE`。原版按整剂计费，最后一剂不足 25 点的差额同样消耗 1 次；不凭空退还半剂。

一次经过同一格，无论需要几剂，只结算 1 燃料和 1 底盘耐久。部分浇水后暂停也结算本次实际改动；补水后再启动算下一次作业。水箱的 `finiteuses` 只表示储水，不再另外作为挂件磨损扣除。

## 实时水分与失败处理

原版只公开布尔型的 `IsSoilMoistAtPoint`，不能用于判断是否浇满。`aom_soil_moisture.lua` 只读这个方法捕获的原版 `_moisturegrid`，每剂前后读取真实数值，不缓存地块水量、不修改原版管理器。雨水、植物耗水、人工浇水和读档后的网格值都会在下一次经过时生效。

原版方法被简单包装时支持沿函数上值查找；接口变化、网格未初始化、缺少 `debug.getupvalue` 或无法确认数值时暂停并提示，不回退成固定浇四次。这个适配依赖原版内部字段，需要在游戏更新后关注兼容性。

原版没有农田覆盖层而实际加水失败时，会退回预留水量且不扣燃料/底盘耐久。如果其他 Mod 在已经加水后抛错，则保留实际进度、按已发生的改动结算并停止；执行后连数值都无法读取时，保留预留扣水并暂停，避免退款造成重复获得水分。

## 新旧存档

新水箱设置 `SetDoesNotStartFull(true)`，空罐、半罐、满罐均显式保存水量，并写入 `aom_water_version=1`。没有独立的第二套水量状态。

| 保存数据 | 恢复规则 |
|---|---|
| 新版 0 / 13 / 40 次 | 原值恢复 |
| 旧版省略 finiteuses（旧满罐 100 次） | 恢复为新版满罐 40 次 |
| 旧版剩余 23 次 | 恢复 23 次 |
| 旧版剩余 100 次或超出容量 | 限制为 40 次 |
| 旧版 0 次 | 保持空罐 |
| 新版有版本字段但遗漏水量 | 按空罐处理，不生成免费水 |

迁移在实体 `OnLoad` 中进行。原版 `EntityScript:SetPersistData` 先加载组件、后调用实体 OnLoad，因此迁移结果不会再次被组件旧数据覆盖。

## 音乐独立接入

`aom_irrigator_music.lua` 是纯客户端模块，与农业调用链分开。菜单「洒水机音乐（需音频包）」可关闭音乐。仅从同步数据读取作业、挂件、余水状态，不发送农业 RPC、不消耗资源、不自动安抚作物。

有真实音频包时，作业开启且有水的洒水机播放《兰花草》；作业关闭、空箱、下车、换件、车辆移除或听者死亡后停止。用骑手位置作为声源，20 游戏单位内随距离衰减，每个客户端选最近的一辆车，只保留一个音乐句柄。客户端每 0.25 秒更新，停止最多有一次刷新间隔的延迟。

模块加载失败、缺少任一音频文件、事件不存在、播放或音量更新抛错时，音乐静音/停止并隔离错误，洒水照常执行。服务端洒水不依赖播放器。

**真实音频包已生成、替换并启用。** 本轮使用 FMOD Designer 4.38.2 正式编译已有 `assets/audio/lanhuacao_loop.wav`，产出 RIFF FEV 与 FSB5 PCM，均已进入运行目录和安装包，默认开启音乐。不是改名的 WAV/MP3，也无需玩家另外制作音频包。

- 项目源文件：`assets/audio/fmod/aom_irrigator_music.fdp`。
- 事件：`aom_irrigator_music/irrigator/lanhuacao`；2D，持续循环，停止时立即切断。
- 原版混音分类：`set_music`，播放器保留距离衰减与配置开关。
- 音频：44.1 kHz、16 bit、立体声，800,680 帧，18.156 秒。
- 校验：FSB 内 PCM 与源 WAV 逐字节一致；FEV 与 FSB 的编译配对值匹配。结构检查拒绝截断、错误类型和错配音频包。
- 编译记录：`assets/audio/fmod/build.json`，记录工程、音频包和 PCM 的 SHA-256。

如果将来更换曲目，可运行 `tools/build_irrigator_music.py --designer /路径/fmod_designercl.exe`。macOS/Linux 可增加 `--wine /路径/wine`；Wine 前缀按本机设置通过环境变量传入。脚本调用原版编译器、校验并安装成对音频包。仅替换已有导出资源时仍可使用 `tools/install_irrigator_music.py /导出目录`。

安装器和自检已兼容真实的 RIFF FEV 与 FSB5；此前只接受 FEV1/FSB3/FSB4 的限制已修正。工具文件和 Wine 仅用于本地编译，不随 Mod 分发。

目前验证包括正式编译成功、包结构与配对、采样逐字节一致、事件路径和循环工程设置，以及客户端播放控制回归；尚未在 DST 中验证最终混音和联机音效。

## 测试结果与边界

运行 `PYTHONPATH=/tmp/pylua python3 tools/selfcheck.py`：**109 项 Lua 5.1 行为回归全部通过，语法、资源和交叉引用检查 0 失败、0 警告。** 洒水流程修复后共 105 项；真实音频接入另新增 4 项资源/注册回归。

流程测试执行原版完整 `farming_manager`、`finiteuses` 以及 `EntityScript` 保存/加载方法原文摘录，覆盖：

- 实际补水动作提示、服务端执行、水壶转移、冰块拆份、满箱不消耗、非水源拒绝。
- 空/半/满罐存读档、旧版缺省满罐迁移、旧空罐保留、重复迁移、换件与 HUD 同步。
- 驶过浇满、按差额补水、雨水/人工浇水/耗水后的实时读取、停车及重复经过满格零消耗。
- 缺水保留进度、补水续浇、最后一剂停机、燃料不足、失败退款和部分成功结算。
- 真实音频包注册、PCM 一致性、循环工程与构建记录、截断和错配拒绝；音乐缺包、开关、距离、多车单曲、停止、错误隔离，以及音乐失败时洒水结果不变。
- 完整串联：空罐 → 补水 → 存读档 → F 启动 → 缺水停止 → 补水 → F 续作 → 换罐 → 下车。

地图、实体底层、网络与声音使用可观察桩。**尚未在 DST 实机验证动画、联机同步或真实音频**；池塘/绿洲直接补水、灭火和作物安抚不在本轮实现范围内。

## 代码位置

- `scripts/aom_irrigator.lua`：水箱、迁移、补水、整格按需浇满。
- `scripts/aom_soil_moisture.lua`：实时水分适配、单剂原版加水及确认。
- `scripts/components/aom_attachment_store.lua`：当前挂件水量存取与单位约束。
- `scripts/aom_drive.lua`：移动触发、单格燃料/底盘结算、停机。
- `scripts/prefabs/aom_attachments.lua`：空罐初始化；`aom_tractor_chassis.lua`：换件及余水同步。
- `modmain.lua`：补水动作、可选音乐资源、客户端播放器装配；HUD 显示余水。
- `tools/tests/test_irrigator_flow.py`、`test_irrigator_music.py`：本轮主流程与音频隔离回归。
