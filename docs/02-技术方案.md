# 农机 Mod 技术路线与核心 API 摸底

> 前提：本机未安装 DST 客户端（Steam 库中只有 Dota 2）。下表**行为**来自官方 Wiki 核对（见 [05-原版农场工具清单.md](05-原版农场工具清单.md)），但**函数签名**必须用游戏自带的 `scripts/` 源码逐个核对（见《03-实施计划》0 号任务）。
>
> **铁律**：拖拉机每个挂件 = 对一格地皮里的坑执行一个**原版 Action**，不新增、不篡改任何农业数值。

## 1. 关键原版对象清单（必须核对）

| 原版工具 / 机制 | 相关原版对象（待核对文件名） | 拖拉机对应挂件 | 必须核对的点 |
|---|---|---|---|
| 园艺耕地机 `farm_plow` | `deployable`、生成 Farm Soil Turf 的流程 | 开垦机 | 15 秒翻地是内置 timer，如何被外部提前触发 |
| 园艺锄 `farm_hoe` / `golden_farm_hoe` | `ACTIONS.TILL`、土坑生成 | 开垦机 | `TILL` 的合法目标与"一格多坑"上限 |
| 种子 / 作物种子 | `plantable`、`farm_plant_defs`、`ACTIONS.PLANTSEED` | 播种机 | 种子如何决定长成什么（随机 vs 指定） |
| 洒水壶 `wateringcan` / `premiumwateringcan` | 对土坑 +25 水分的执行逻辑、`moisture` | 洒水机 | 补水函数名与上限 100 的保护 |
| 肥料（`manure` / `guano` / `compost` / `growthformula_*` 等） | `USEITEM` 的养分加成表、3 种养分字段 | 施肥机 | 原版加成表；"3 种养分"在代码里的字段名 |
| 铲子 `shovel` | `ACTIONS.DIG` | 除草机 | 杂草 `weed_*` 与残渣 `farm_soil_debris` 的 tag |
| 收获 | `ACTIONS.HARVEST`、`farmplant` 的 harvested 回调 | 收割机 | 巨大化作物如何生成、种子返还 |
| 巨大化作物 | `*_oversized` prefab、锤子 `HAMMER` | **不做** | 仅用于确认"原地保留"不会掉地上 |
| 下沉危险 | `weed_firenettle`（火荨麻）、`weed_ivy`（荆棘藤） | 不做 | 确认不会被拖拉机触发 |

## 2. "拖拉机"落地方式三选一

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 骑乘载具 | 底盘挂原版 `rideable` + `locomotor`，角色用 `Rider:Mount` 骑上去 | 真驾驶感；速度自动继承 `locomotor.runspeed` | 依赖原版骑乘状态机，角色会切 `wilsonbeefalo` 动画库 | **V1 采用** |
| B. 可放置机械 | `MakePlacer` 放置一台固定建筑 | 实现快 | 无驾驶手感 | 已废弃 |
| C. 跟随宠物 | 像 WX-78 机器人一样"召回/跟随"，玩家走路它跟着 | 最省事 | 少了驾驶感，更像宠物 Mod | V2 可叠加 |

> **推荐 B**：V1 先用"可放置 + 驾驶模式"跑通完整玩法，等 V2 再把底盘升级成真正的载具。这样 2 周内能出可玩 Demo，风险可控。

## 3. 挂件系统的技术设计

### 3.1 数据结构

```lua
-- 底盘（建筑）上挂一行 itemslot，槽位类型 "attachment"
inst.components.container:WidgetSetup("tractor_attachment_slot")  -- 1 个槽
inst.components.container.canbeopened = true

-- 挂件（物品）识别
-- 用 tag 而非 prefab 列表：挂件都带 "tractor_attachment" tag
-- 具体类型在 prefab 上写入 inst.attachment_type =
--   "plow"（园艺耕地机+园艺锄）/ "seeder"（种子）/ "irrigator"（洒水壶）
--   / "fertilizer"（肥料 USEITEM）/ "weeder"（铲子）/ "harvester"（HARVEST）
-- 装载时：
local item = tractor.components.container:GetItemInSlot(1)
tractor.attachment_type = item and item.attachment_type or nil
tractor:PushEvent("attachment_changed", { type = tractor.attachment_type })
```

### 3.2 作业态主循环（核心伪代码）

```lua
-- 每 0.25s tick 一次（服务端），只在"驾驶"时运行
local function OnWorkTick(inst)
    local driver = inst.driver
    if not driver or not driver:IsValid() then return inst:StopWork() end

    -- 1. 燃料/电力
    if not inst:TryConsumeFuel() then return inst:StopWork("no_fuel") end

    -- 2. 决定下一步位置：沿玩家朝向推进一个作业间距
    local target = inst:GetNextWorkPosition(driver)   -- 例如 width = 1.5 格地皮
    -- 3. 根据挂件执行：每个分支都只是"对一格地皮里的坑执行原版 Action"
    local att = inst.attachment_type
    if att == "plow" then
        inst:PlowTile(target.x, target.z)        -- 原版：铺 Farm Soil Turf + TILL
    elseif att == "seeder" then
        inst:SeedTile(target.x, target.z)        -- 原版：PLANTSEED
    elseif att == "irrigator" then
        inst:WaterTile(target.x, target.z)       -- 原版：洒水壶 USEITEM（+25，上限 100）
    elseif att == "fertilizer" then
        inst:FertilizeTile(target.x, target.z)   -- 原版：肥料 USEITEM（补所选养分）
    elseif att == "weeder" then
        inst:WeedTile(target.x, target.z)        -- 原版：铲子 DIG（只铲杂草与残渣）
    elseif att == "harvester" then
        inst:HarvestTile(target.x, target.z)     -- 原版：HARVEST（巨大化原地保留）
    end

    -- 4. 耐久 & 视觉
    inst.components.finiteuses:Use(1)
    inst.SoundEmitter:PlaySound("dontstarve_DLC003/common/objects/.../work")
end
```

### 3.3 关键：**不要**直接改作物组件

所有挂件都只是"**把原版 Action 对一格执行**"，绝不写农业数值：

- **犁地**（园艺耕地机 + 园艺锄）：先调原版耕地机生成 Farm Soil Turf 的流程（`farm_plow` 的 deploy 逻辑），再对土坑走 `farm_hoe` 的 `TILL` 逻辑。**不要**自己 `SpawnPrefab("farm_soil")` 然后手填数据。
- **播种**（种子）：走原版 `farm_soil` 上的 `PLANTSEED` 代码路径（`farm_plant_defs` 决定长成什么），**不要**自己选 prefab。
- **浇水**（洒水壶）：复刻洒水壶 `+25 水分` 的执行逻辑，直接调原版给土坑补水的函数；上限 100 由原版逻辑保证，**不要**写 `moisture = 100`。
- **施肥**（肥料）：复刻肥料 USEITEM 的养分加成表（粪 +8 粪肥 / 鸟粪 +16 / 堆肥 +24 等），**不要**自造养分数值。
- **除草**（铲子）：只对带 `weed_*` / `farm_soil_debris` prefab 的实体走 `DIG`，绝不碰作物与移植植物。
- **收割**（HARVEST）：直接调 `farmplant:Harvest` 类原版收获入口，产出、种子返还、巨大化判定全交给原版。
- 以上每一条都必须在 0 号任务里对照 `scripts/` 打勾，并在 `docs/api-notes.md` 记录真实函数名（Wiki 给的是**行为**，不是代码签名）。

## 4. 两个容易被做坏的挂件

### 4.1 施肥机（对应"肥料 USEITEM"）

原版**没有施肥工具**，肥料是物品，右键对土坑/植物"使用"来补某种养分。所以施肥机要做的是：

```lua
-- 玩家在挂件 UI 里选择肥料类型（粪/鸟粪/堆肥/生长素…）
-- 作业时：对车前那一格的土坑执行一次原版肥料 USEITEM
function inst:FertilizeTile(cx, cz)
    local soil = self:FindFarmSoilAt(cx, cz)          -- 该格的 farm_soil
    if not soil then return end
    local fert = self:PopFertilizer()                  -- 从挂件的肥料仓取 1 份
    if not fert then return self:NotifyEmpty("no_fertilizer") end
    -- 走原版 USEITEM 的同一条代码路径，而不是手写 +8/+16/+24
    soil.components.<原版肥料处理入口>(fert, self.driver)
end
```

- **不做"智能施某种养分"**：原版肥料加什么就加什么；挂件只是"把肥料撒到一整片坑上"。
- 基肥/追肥的先后顺序由玩家决定（选肥料类型），代码不替玩家做农业决策。

### 4.2 采收挂件（对应 `HARVEST`，不做巨大化处理）

```lua
function inst:HarvestTile(cx, cz)
    for _, e in ipairs(self:FindMaturePlantsAt(cx, cz)) do
        -- 直接调用原版收获入口，产出/种子/巨大化判定全部交给原版
        e:PushEvent("harvest", { harvester = self.driver })
    end
end
```

- **巨大化作物不自动锤**：原版流程是"收获 → 巨大作物落地 → 玩家用锤子砸"。收割机让巨大作物正常落地，**不接管**后续的锤子步骤（设置里保留一个默认关闭的二段开关）。
- 不做"自动进背包"：抛出物品让玩家自己捡，保持原版掉落体验（设置里可开）。

## 5. 客户端 / 服务端职责

| 模块 | 服务端 | 客户端 |
|---|---|---|
| 底盘实体、挂件槽、燃料、耐久、肥料仓、水箱 | ✅ 权威 | 只读显示 |
| 作业判定（犁/种/浇/肥/铲/收） | ✅ 全部 | ❌ |
| 骑乘（上下车） | 原版 `rider:Mount/Dismount` | 右键动作 |
| UI（挂件面板、油量、作业进度） | ❌ | ✅ |
| 动画/音效/粒子 | 触发 netvar | 播放 |

`modinfo.lua` 中：`all_clients_require_mod = true`（必须，因为新增了 prefab 和 RPC），`server_filter_tags = {"farm","automation","tractor"}`。

## 6. 联机同步要点

- 底盘血量/燃料/耐久用 `netvar` 同步（`net_float` / `net_entity`）。
- 挂件变化用 `SleepingBag` 风格的 `net_event` + `PushEvent`，避免每帧轮询。
- 骑乘状态由原版 `rider` 组件同步；车被移除时用 `onremove` 强制 `ActualDismount`，避免角色卡在骑乘态。
- 作业期间如果司机死亡 → 立即停机 + 广播音效，避免"尸体开车种满全图"。
- 工作频率默认 0.25s，`TheSim:GetTickTime()` 保护，避免收集端累计误差。

## 7. 性能红线

- 单次 tick 内只处理**车前的 1 格地皮**（原版一格的土坑数有限），绝不遍历全图农田。
- 所有范围查询使用 `TheSim:FindEntities(x, z, R, {}, nil, tags)`，R ≤ 2 格地皮。
- 掉落的物品默认落地（保持原版），设置里可开"直接进背包"；巨大化作物一律原地落地。
- 离屏（无玩家在 40 格内）时底盘自动停机，不做后台挂机——原版农场本身就要求玩家在附近才会成长。
