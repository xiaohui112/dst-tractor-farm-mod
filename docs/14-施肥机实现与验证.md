# 施肥机实现与验证

施肥机现在对当前农田按需补齐三类养分，保持原版每份肥料的养分与使用次数。新旧存档继续使用 `aom_fertilizer` prefab 与 `fertilizer` 挂件类型，显示名改为「施肥机」。

## 操作与默认目标

1. 把施肥机放到拖拉机第1格。
2. 下车手持肥料右键拖拉机装料，或通过容器把肥料放入第2～9格。
3. 骑上拖拉机，按F开启作业。驶入地块时读取实时养分，默认以生长素、堆肥、粪肥各100为目标。
4. 同一格需要多份肥料时在这次经过中完成，不需要停车等待；停车不重复施肥。
5. 需要施肥但没有合适肥料时自动关闭作业，提示尚缺的养分类别。已增加的养分保留，补料后按F只补差额。

施肥对象仅限当前农田土壤，不会优先给附近的浆果丛、草丛或旧式 crop 组件施肥，也不会越界操作相邻地块。已满农田、非农田不扣料、不扣燃料、不磨损底盘。

## 选肥和用量

每次使用前重新读取原版 `farming_manager:GetTileNutrients`，逐份读取仓内肥料组件的 `nutrients`，计算本次可增加的实际养分。

选择顺序为：

1. 跳过已耗尽、零增益或养分参数无效的肥料。
2. 优先选择有效增量占整份养分比例更高的肥料，减少溢出。
3. 有效率相同时，优先有效增量较大的肥料。
4. 完全相同时保留料仓槽位顺序。

这是一份一份选择的确定性策略，不承诺全局最少用料。原版按整份使用；例如只差1点时，仍可能需要用掉一整份肥料，溢出部分由原版100点上限钳制，不凭空退回半份。

原版三类养分以整数存储。每次必须确认至少一项实际增加；批次最多执行 `3 × 100` 次，足够覆盖每份只增加1点的情况，避免异常肥料导致无限循环。

## 物品归属、堆叠和多次用量

装料共享接口已修复：先检查机器容器实际可接纳数量，再从原库存移出或拆出可装入的数量，最后交给机器。原版 `Stackable:Get` 会让拆出物继承原 owner，因此拆份后明确清除该继承归属，再入机器，避免同一实体同时挂在两个所有者下面。

- 满仓：原物品保持原槽位和归属。
- 部分容量：只装入能接纳的份数，其余仍在玩家原库存。
- 中途容量变化：保留实际装入的数量，退回剩余物品。
- 入仓失败：退回原所有者/槽位；来源无法接回时，在来源位置保留可见掉落物。
- 已在本机的物品：拒绝重复装入。

施肥时不把肥料从料仓拿走。养分通过原版 `AddTileNutrients` 增加，确认生效后仅调用一次原版 `fertilizer:OnApplied`：

- 堆叠肥料由原版拆掉并消耗一份。
- 多次用量肥料由原版扣一次 `finiteuses`，剩余物品继续留在原槽位。
- 最后一次使用和返空瓶等行为由原版回调处理。
- 保留原版施肥音效（整格批处理播放一次，避免多份音效叠加）和 `ondeployed_fertilzier_extra_fn` 附加回调。

没有直接调用手持物品 `Deployable:Deploy`，因为原版手持部署入口会拒绝骑乘玩家；挂件使用相同的底层养分/肥料组件完成机械化作业。

## 消耗结算和面板

| 情形 | 肥料 | 燃料 | 底盘耐久 |
|---|---|---:|---:|
| 一次经过补齐当前格 | 按实际原版用量 | 1 | 1 |
| 部分施肥后缺少对应肥料 | 保留实际用量并暂停 | 1 | 1 |
| 满肥、非农田、停车 | 0 | 0 | 0 |
| 施肥前无燃料、无合适肥料或读取失败 | 0 | 0 | 0 |
| 加养分没有生效 | 不调用 OnApplied | 0 | 0 |

加养分后其他回调出错时，已发生的实际改动仍结算一份肥料和一次地块作业，并暂停；写入后无法重新读取时也按已执行的一次保守结算并暂停，避免反复试作业。

移除施肥机原先不起作用的100次 `finiteuses`，只计肥料消耗和底盘磨损。旧存档挂件中遗留的该组件数据被忽略，挂件ID保持不变。

HUD显示总剩余可施用次数，而不是只数物品件数；同一物品的剩余次数可随原版组件更新。另显示按槽位排列的前3种肥料用量，更多类型用「等N种」提示；容器中仍可查看全部物品。

## 存档

不另存一份肥料余额。堆叠数量、多次用量、物品归属由原版 Container、Stackable、FiniteUses 和 EntityScript 保存/加载。换挂件不会消费料仓内的肥料；地块真实养分由原版世界组件存档。补料后重新开启会以实际地块养分为准。

## 验证

`PYTHONPATH=/tmp/pylua python3 tools/selfcheck.py`：**143项行为回归通过，静态检查0失败、0警告**。

本轮新增33项施肥流程测试和1项面板/交互测试，更新原先「一格只用一件」的旧测试。重点覆盖：

- 三类补齐、满肥零消耗、无效首槽跳过、溢出优先级、非农田和附近植物不受影响。
- 多次用量留仓、原版堆叠消耗、最后一次返空瓶、与原版部署回调的单份效果一致。
- 缺肥提示、补料续作、跨格补齐、停车及重复经过满格零消耗、1燃料完成整格。
- 完整归属转移、满仓原位保留、部分装入、入仓失败退回、不能接回时原位掉落。
- 原版容器保存/加载保留剩余次数与堆叠、旧挂件兼容、余量同步和过期监听清理。
- 加养分失败、部分成功后异常、附加回调异常、300次有效应用的有限批处理。
- 串联流程：装料 → F启动 → 缺肥停止 → 补料 → 保存/读档 → F续作 → 下车。

测试运行真实原版 FarmingManager、Fertilizer、FiniteUses、Stackable、Container、InventoryItem 的相关方法及 EntityScript 存读档方法，原版返空瓶和部署回调使用原文摘录。地图、实体、库存底层、网络、物理与声音表面仍为桩，尚未完成 DST 实机和联机验收。
