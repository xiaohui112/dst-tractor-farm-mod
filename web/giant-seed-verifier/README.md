# Mod 巨大化播种验证器

独立的本机网页，直接调用仓库 `mod/Tractor/scripts` 中的原始 Lua 5.1 模块。JavaScript 负责场景输入、绘图和导出，不包含另一份播种算法。

## 打开

双击 `打开巨大化播种验证器.command`。启动器打开本机浏览器，不需要联网。关闭终端窗口或按 Ctrl+C 可停止服务。

也可以在此目录执行：

```sh
python3 server.py --open
```

默认地址 `http://127.0.0.1:8877`；端口被其他程序占用时选择可用端口。只监听本机。启动器按后端签名识别服务，只复用同版后端；旧服务仍在运行时自动选择新端口，避免新Lua算法搭配旧场景适配器。更新后重新双击启动器打开。

本机已准备 Python 3.9 + Lupa/Lua 5.1 运行环境，保存在被 Git 忽略的 `.runtime`。新机器需要为自己的 Python 安装 `lupa`：`python3 -m pip install --target .runtime lupa`。如果移动此网页目录，需要通过 `TRACTOR_MOD_SOURCE` 指定 Mod 根目录。原版数据默认从本机 Steam DST 的 `scripts.zip` 读取，也可通过 `DST_GAME_SCRIPTS` 指定。

## 使用

- 选择“巨大化·模版”或“巨大化·最优”、季节和库存。输入有效宽高会自动填满矩形；随后点击“编辑地皮”手动修改不规则范围。改变尺寸会重新填满矩形。
- 种子数量点击后全选，可直接键入替换；编辑时可暂时清空，离开输入框后按0处理。
- 每块地皮提供3×3个完整空坑，坑距与 Mod 九宫格一致。起点控制 Mod 实际扫描的连通区域，断开的田不会算入本次播种范围；模版策略不设固定连通地皮上限；最优策略保持64块上限。网页宽高及导入地皮数量不再沿用32／1024的旧检查，仍受浏览器与机器资源限制。
- 点击“生成播种布局”，原始 Mod 决定用哪些种子、播种数量与每个坑位。取消计算或修改输入会取消旧任务。
- 画布逐株检查应季、同族、逐格养分互补和拥挤上限，满足时显示原版巨大化图标，否则显示成熟图标。巨大化为全程养护达标时的预期：游戏最终还会结算水分、实际养分、照料与杂草等压力，本页不模拟生长过程。
- 点击作物查看原版同族半径、数量和巨大化条件；再次点击同株、点击画布空白或按Esc取消检查；点击画布上方的库存使用项可突出显示一种作物。
- “适应画布”按实际农田外接范围等比铺满可用宽高，不限制放大倍数；编辑地皮时显示完整网格。作物图标随农田一起放大，四季采用青绿、干黄、褐土与覆雪地皮外观。
- 桌面使用视口自适应布局，库存使用和坑位检查置于画布上方；库存使用区仅显示输入库存大于0的作物，即使本次未使用也保留，按宽度自动换行，不在面板内滚动；手机采用纵向布局。页面配色与地皮画布参考 [DST Farm Planner](https://erocrizs.github.io/dst-farm-planner/)。
- 内置番茄土豆、最低库存、多种尾数、T形、U形、环形、冬季、断开区域和64格大田场景。
- 导出可选完整验证结果、输入场景、`dst-farm-planner` 兼容布局。导入接受本页保存的输入场景或完整验证结果；农田规划器格式仅作为对照导出，不作为输入。

## 算法来源与一致性

每次任务创建独立 Lua 5.1 环境，重新读取当前 Mod 文件；不会沿用上一次任务的 Lua 模块缓存：

- `aom_dynamic_farm.lua`：从起点扫描实际连通田、生成布局、自身校验。
- `aom_seed_balance.lua`：从原版定义计算净变化，枚举逐格互补数量组合与安全上界；不读取当前土壤肥力。
- `aom_seed_catalog.lua`：由审核后的[角色格子目录](../../docs/template-catalog/README.md)构建的静态数据，包含去重方向、角色坑位、库存与每地皮作物组成。
- `aom_seed_template_data.lua`：无状态的真实坑位筛选和完整块逐坑比对，两种策略可共用。
- `aom_seed_templates.lua`：有界整块选配与替换，先比株数，再比留空集中、整齐和稳定编号/方向/位置；保持内部坑位。
- `aom_seed_initial.lua`：最优策略自己的初始见证构造；静态模版只作为额外合法候选，不调用模版策略入口。
- `aom_seed_packing.lua`：先证明最大数量，再调用一次排列整理；分别记录两个阶段的CPU耗时。
- `aom_seed_exact.lua`：完整数量约束搜索，未排除更大数量前不返回较少株数。
- `aom_seed_feasible.lua`、`aom_seed_heuristic.lua`：提供合法下界/上界见证；截断不用于证明不可行。
- `aom_seed_layout.lua`：在最大数量固定后，按分散程度、同族距离、整齐评分依次整理。
- `aom_seed_strategy.lua`、`aom_farm_registry.lua`、`aom_crop_state.lua`：原始规则及作物识别。
- `components/aom_attachment_store.lua`：使用真实物料仓组件统计场景库存。

地图、土坑、种子实体与容器 API 在 `lua_bridge.lua` 中适配；仅为算法提供测试输入。进度包装函数只转发参数和返回值，不改预算、候选或评分。原版作物定义直接读取游戏文件，季节、同族半径、同族下限、坑距，以及消耗/回补所用的2、4、8级养分常量均采用本机原版值。和播种无关的生长时间、美术常量使用占位值，播种逻辑不会读取它们。

页面显示当前版本、全部规划模块 SHA-256 以及它们是否与本机已安装 Mod 一致。完整结果保留场景、原始坐标、源码哈希、原版定义哈希、实际养分常量、逐格净变化、耗时与校验结果。若算法文件在计算期间改变，拒绝该次结果，要求重新生成。

“巨大化·模版”显示固定模版布局及准备/选配回填/校验评分耗时，不承诺全田最大。“巨大化·最优”的“已证明最大合法播种量”只在数量已被证明最大时显示。合法见证达到安全上界即可完成证明；否则完整排除更大的数量。未完成的任务继续搜索，可取消，不用较少株数冒充最终计划。排列整理仍有预算，不表示其全局最优。界面和JSON分别显示最大数量求解、紧凑/整齐优化的CPU耗时，并保留端到端墙钟时间；耗时只统计，不改变原算法分支或预算。加权 `score` 仅保留为旧结果的诊断字段，实际整理按 `fragmentation → family → tidy`。独立Python检查只验证结果，不修改布局。

“锁定模版”选择某个编号后，只用该完整图案选配，可重复多块；改回“自动整块选配”恢复全目录选择。结果下方和导出JSON记录每块模版编号、世界原点、方向与角色作物。两组双地皮16株与一组四地皮32株可分别锁定检查，不能按库存相同合并。任务结果和计时来自本轮设备任务，不读共享的最优模块`last_report`。

本页不模拟游戏执行时的驾驶路径、世界障碍、已有作物、联网同步、逐坑播种时的动态变化，也不模拟生长、施肥、水分和照料。本页不读取或限制地皮当前养分；会严格校验每块地皮的配比净变化为零。单格双种4＋4保留中心坑，库存充足也不会填成5＋4；明确编号的四格番茄＋土豆/茄子32株按原图留四角，不改为中心空坑。

Mod的数量构造现在包含固定目标配额联立求解、互补库存子组及紧凑地皮子集见证，并由完整约束搜索负责未达到上界的数量证明。网页只调用这些Mod函数，不提供另一套实现；模版数据也直接来自Mod。详细回归和两阶段计时见[0.5.13报告](../../docs/evidence/0.5.13-seed-optimization-report.md)。

## 验证

```sh
python3 -m unittest discover -s tests -v
node --test tests/test_crop_display.cjs
```

回归还需要仓库 `requirements-dev.txt` 中的 SciPy，仅用于独立数量/空间校验；网页运行不依赖它。

测试通过独立场景适配器 `tools/seed_strategy_audit.py` 调用同一份真实 Mod，与网页后端逐坑比较实际坐标与作物：四季×16种地形，再加12个固定随机库存/形状场景，共76组。另有库存边界、断开区域起点、超限、取消、源码变更后重新读取、HTTP接口及输入错误校验。

在仓库根目录运行完整场景回归并导出分阶段计时：

```sh
python3 tools/seed_strategy_audit.py --suite all --jobs 4 --case-seconds 30 --output outputs/seed-regression.json
```

同目录生成 `seed-regression.timings.csv`（逐例结果）和 `seed-regression.timing-summary.json`（P50、P95、最大值）。`maximum_quantity_seconds` 包括配比准备、合法候选构建和最大数量证明；`arrangement_seconds` 只包括数量证明后的同族紧凑与排列优化。两者均为进程CPU秒，`wall_seconds` 是整个场景的墙钟秒。并发执行时二者不能混用，也不包含游戏协程跨帧等待的时间。

`--case-seconds` 仅为回归工具的墙钟中断上限，不改变Mod搜索规则。超时记录当前阶段、已消耗CPU时间及阶段完成标志。未完成数量证明时，最大播种数留空；仅排列中断时保留已证明数量和数量耗时，最终布局仍标记未完成。超时与校验失败分别统计，均不计入通过案例或整例完成耗时的分位数；另按阶段完成标志分别统计各阶段耗时。汇总同时给出全部已完成案例和播种量大于零的案例，避免空库存造成耗时统计偏低。去掉该参数即可等待完整证明。

刷新页面时，首屏直接附带本机原版作物定义，季节和库存不再等待额外请求。预设场景异步加载，失败不影响手动配置和生成；加载失败时左栏会显示原因和“重新连接”入口。

## 作物图标

成熟与巨大化图标来自本机 DST 的原版资源，版权归 Klei Entertainment。新增的14张 `*_oversized.png` 从 `images.zip` 的 inventoryimages 图集中按 XML UV 提取。重新提取：

```sh
python3 extract_crop_icons.py
```

脚本依赖 Pillow 和 `~/.local/bin/ktech`，可用 `--game-images`、`--ktech` 指定位置。网页运行不需要这些提取工具。
